### 2-2. 프롬프트 방식별 비교

| 방식 | 특성 | JSON 준수율 | 적합 상황 |
|------|------|-----------|---------|
| **Zero-shot** | 간결, 빠른 생성 | 높음 | 단순 식단, 빠른 응답 |
| **Few-shot** (권장) | 예시 기반 학습, 품질 안정 | 매우 높음 | 기본 식단 생성 |
| **CoT** | 추론 과정 포함, 영양소 정확 | 중간 (추론 부분 분리 필요) | 제약사항 복잡한 경우 |

| "유산소 심폐 체력" | 러닝, 줄넘기, 사이클 | (빈 결과) | BM25가 의미 검색에 강점 |

- **권장:** 필터(정확 매칭) + BM25(의미 검색) 하이브리드 사용

## 7. 한계점 및 향후 개선

1. **Ollama 로컬 GPU 의존** — 응답 시간 10~30초, 서버 배포 시 GPU 서버 필요
2. **학습 데이터 부족** — 목표분류 100개, 감성분석 40개 → 500개+ 확보 필요
3. **감성 분석 정확도** — 규칙 기반 70% → KcBERT 파인튜닝으로 85%+ 목표
4. **식단 칼로리 정확도** — LLM 생성 식단의 영양소 오차 → 식품 API 교차검증 강화
5. **실시간 연동** — 웨어러블 기기, 실시간 트래킹 미구현
6. **다국어 확장** — 현재 핵심 UI만 번역 → 페이지 내부 콘텐츠까지 완전 번역 확장
7. **데이터 저장** — JSON 파일 기반 → SQLite/PostgreSQL 전환으로 동시접속 안정성 확보
