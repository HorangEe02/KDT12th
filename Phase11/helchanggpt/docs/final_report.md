## 2. 선택한 주제와 이유

### 주제: AI 기반 맞춤형 피트니스 토탈 코칭 서비스

사용자가 자연어로 신체 정보와 운동 목표를 입력하면, **4단계 NLP 파이프라인**(프로필 분석 → 식단 생성 → 운동 루틴 → 동기부여 피드백)을 통해 개인 맞춤형 건강 관리를 제공하는 서비스.

### 선정 이유

| 구분 | 내용 |
|------|------|
| **시의성** | 2025~2026년 건강관리 트렌드에서 AI 피트니스 수요 급증. 헬스케어 NLP 시장 2035년 230억 달러 전망 |
| **NLP 적합성** | 텍스트 분류, NER, 키워드 추출, 텍스트 생성, 감성 분석, 요약, 검색 등 거의 모든 NLP 기법을 하나의 서비스에서 활용 |
| **교육적 가치** | 복수 NLP 기법을 하나의 파이프라인으로 통합 설계하는 실무 경험 |

## 5. 프롬프트 설계 방식

### 3가지 프롬프트 비교

**Zero-shot:** 지시만으로 생성
```
"아래 사용자 정보를 바탕으로 하루 식단을 생성해주세요. [사용자 정보]..."
```

**Few-shot (권장):** 예시 포함
```
"[예시 1 - 체지방감소 목표, 남성, 1800kcal]
입력: 28세 남성, 180cm 85kg...
출력: {"meals": {"breakfast": ...}}
이제 아래 사용자 정보로 식단을 생성해주세요."
```

**Chain-of-Thought:** 단계별 추론
```
"Step 1) 사용자 상황 분석
Step 2) 끼니별 칼로리 배분
Step 3) 음식 선택 기준 설정
Step 4) 식단 구성 및 영양소 계산
Step 5) 검증"
```

### 프롬프트 비교 결과

| 방식 | JSON 준수율 | 영양소 정확도 | 적합 상황 |
|------|-----------|-----------|---------|
| Zero-shot | 높음 | 중간 | 빠른 생성, 단순 식단 |
| **Few-shot** | **매우 높음** | **높음** | **기본 권장** |
| CoT | 중간 | 높음 | 제약사항 복잡한 경우 |

## 6. 파라미터 조정 내용

### temperature 튜닝

| temperature | 식단 다양성 | 영양소 정확도 | 채택 여부 |
|------------|----------|-----------|---------|
| 0.3 | 낮음 (반복적) | 높음 | 인바디 파싱 전용 |
| **0.7** | **균형** | **중간** | **기본값 채택** |
| 1.0 | 높음 (창의적) | 낮음 | 다양한 탐색용 |

### max_tokens 조정

- qwen3.5 reasoning 모델: 사고 과정에 토큰 소모 → `max_tokens: 2000~4000` 필요
- exaone3.5: 직접 응답 → `max_tokens: 500~2000` 충분

### BMR 공식 선택

- **Mifflin-St Jeor 채택** (ADA 권장)
- Harris-Benedict 대비 평균 -91kcal (과대추정 방지)
- 인바디 BMR 측정값이 있을 경우 인바디 우선 사용

## 8. 잘 된 사례 / 실패 사례

### 성공 사례

1. **NER 100% 정확도** — 정규식 패턴이 "숫자+단위" 구조에 완벽 매칭. "30대" → 35세 변환, "센티/킬로" 비표준 단위 처리 성공
2. **인바디 교차 검증** — 체중(43.6+11.7+3.81+6.4=65.5kg) 구성 검증, BMI 역산 검증 모두 통과
3. **피드백 모드 다양화** — 5종 피드백 모드(코치/친구/교관/매미킴/해병문학)가 사용자 선호에 맞는 톤으로 동일 결과를 다르게 전달

### 실패 사례

1. **Qwen 3.5 빈 응답** — reasoning 모델이 사고 과정에 토큰을 소모하여 `content`가 비어 반환. → `max_tokens` 2000+ 으로 해결
2. **exaone3.5 미설치 404** — 기본 모델이 미설치 상태에서 모든 API 실패. → 사용 가능 모델 자동 감지로 해결
3. **감성 분석 "줄었다" 미인식** — "체중이 2kg 줄었다!"에서 "줄었다"가 긍정 키워드에 없어 중립 판정. → 키워드 사전 확장 필요

## 9. 개선 시도

### 단계별 고도화 경로

```
[규칙 기반 baseline] → [BERT 파인튜닝] → [LLM 프롬프트] → [UX 고도화]
     ↓                      ↓                   ↓                ↓
  NER 100%          KcBERT 학습 데이터 100개    EXAONE 3.5 연동     라이트 모드
  분류 F1 0.849     (500개 확보 후 학습 예정)    Few-shot 최적        다국어 UI
  감성 70%          (감성 분석 파인튜닝 예정)     피드백 모드 5종      데이터 저장
```

### 주요 개선 내역

1. **BMR 공식 변경:** Harris-Benedict → Mifflin-St Jeor (ADA 권장, 현대 인구에서 더 정확)
2. **BMI 기준 세분화:** 4단계 → 6단계 (KSSO 대한비만학회 기준 반영)
3. **건강 위험도 추가:** 내장지방/복부비만/근감소증(SMI) 스크리닝
4. **피드백 모드 확장:** 기본 3종 → 매미킴/해병문학 추가 (사용자 재미 요소)
5. **파일 업로드 다양화:** 이미지 + CSV + PDF + Word + Excel 지원
6. **라이트/다크 모드 구현:** CSS 변수 기반 테마 시스템으로 라이트 모드(부드러운 그린 `#2e7d32`) + 다크 모드(네온 그린 `#a2fe00`) 전환 지원. 스크롤바, 그라디언트, 글로우 애니메이션까지 테마 반영
7. **다국어 UI 지원:** 경량 번역 딕셔너리(`translations.js`) + `t()` 훅 기반 한국어/영어/일본어 핵심 UI 번역 (네비게이션, 설정, 로그인, 페이지 헤더 등 ~50키 × 3개 국어). i18n 라이브러리 없이 Context 기반 구현
8. **식단/운동 데이터 영속화:** 생성된 식단·운동 루틴을 JSON 파일로 저장/조회/삭제 API 6개 엔드포인트 추가. 페이지 새로고침 후에도 최근 데이터 자동 복원, 저장 이력 탭에서 과거 식단/루틴 불러오기 가능
9. **식단 사이드 미리보기:** AI 대화 탭에서 식단 생성 시 탭 전환 없이 사이드 패널에서 3일치 식단 요약(날짜 탭 전환, 끼니별 메뉴/칼로리/음식 목록) 확인 가능
10. **해병문학 구호 수정:** "충성!" → "필승!" (해병대 정확 경례구호 반영, 1976년 이후 해병대 공식 구호)

## 10. 한계점 및 향후 개선 방향

### 한계점

| 항목 | 현재 한계 | 영향 |
|------|---------|------|
| **GPU 의존** | Ollama 로컬 GPU 필수, 응답 10~30초 | 동시 접속 제한 |
| **학습 데이터** | 목표분류 100개, 감성분석 40개 | BERT 파인튜닝 불충분 |
| **감성 분석** | 규칙 기반 70% | 미묘한 감정 구분 한계 |
| **식단 검증** | LLM 생성 영양소의 실제 정확도 미검증 | 식품 API 교차검증 필요 |
| **데이터 저장** | JSON 파일 기반 (식단/운동/일기 영속화 완료) | 동시 접속 시 충돌 가능 → DB 전환 필요 |
| **다국어 번역** | 핵심 UI만 번역 (네비·설정·로그인) | 페이지 내부 상세 콘텐츠 한국어 고정 |

### 향후 개선 방향

1. **KcBERT 파인튜닝** — 목표분류 500개, 감성분석 200개 데이터 확보 후 학습 → F1 0.90+ 목표
2. **SQLite/PostgreSQL 전환** — JSON 파일 → DB로 안정성 향상
3. **실시간 연동** — 스마트워치 데이터 연동, 운동 중 실시간 피드백
4. **모바일 앱** — React Native 또는 Flutter로 모바일 확장
5. **식품 API 교차검증** — LLM 생성 영양소를 식약처 API로 실시간 검증
6. **다국어 확장** — 현재 핵심 UI 번역(한/영/일) → 페이지 내부 상세 콘텐츠까지 완전 번역 확장
