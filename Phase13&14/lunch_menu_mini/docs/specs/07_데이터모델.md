# 07. 데이터 모델 명세

## 0. 개요

Mini는 **SQLite** 기반의 단일 DB(`mini.db`, 파일 ~360KB ~ 수MB)를 사용하며, **SQLAlchemy 2.0** Declarative Base 패턴으로 13개 테이블을 정의합니다. lunch-api와 nlp-api 두 서비스가 동일한 DB 파일을 공유 볼륨(`mini-db`)으로 마운트하여 일관된 데이터에 접근합니다.

### 0.1 ER 개요
```
teams ─────┐
   │ 1     │
   ├─ users ──┐
   │          │ 1
   │  ┌───────┼─────────────────────┐
   │  │       │                     │
   │  N       N                     N
   ├─ votes  meal_history          buddy_posts ─── buddy_joins
   │  │       │                     │ 1               N
   │  N       │                     │
   └─ vote_sessions  visit_history  │
                       │            │
                       │            │ 1
                  restaurants ──────┘
                       │ 1
                       ├─ nutrition_info
                       ├─ reviews (NLP A1)
                       ├─ menu_normalization (NLP B1)
                       └─ vetoes
                  
                  weather_logs (독립)
                  chat_messages
                  nutrition_reports (NLP D5)
```

### 0.2 SQLAlchemy 2.0 패턴
```python
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship
from sqlalchemy import String, Integer, Float, DateTime, ForeignKey, JSON

class Base(DeclarativeBase):
    pass
```

### 1.1 `restaurants` — 음식점

```python
class Restaurant(Base):
    __tablename__ = "restaurants"
    
    id:            Mapped[str]   = mapped_column(String(64), primary_key=True)  # Kakao place_id
    name:          Mapped[str]   = mapped_column(String(100), nullable=False)
    category:      Mapped[str]   = mapped_column(String(50))                    # 한식 / 중식 / 일식
    sub_category:  Mapped[str]   = mapped_column(String(100))                   # 찌개,전골 / 짜장면 ...
    lat:           Mapped[float] = mapped_column(Float, nullable=False)
    lng:           Mapped[float] = mapped_column(Float, nullable=False)
    address:       Mapped[str]   = mapped_column(String(255))
    phone:         Mapped[str]   = mapped_column(String(30))
    place_url:     Mapped[str]   = mapped_column(String(500))
    distance_m:    Mapped[int]   = mapped_column(Integer, default=0)
    distance_score: Mapped[int]  = mapped_column(Integer, default=0)            # 0–100
    rating:        Mapped[float] = mapped_column(Float, default=0.0)
    visit_count:   Mapped[int]   = mapped_column(Integer, default=0)
    is_active:     Mapped[bool]  = mapped_column(Boolean, default=True)
    
    # NLP A1 (Sentiment) — 동적 추가 컬럼
    sentiment_score:        Mapped[float | None] = mapped_column(Float)         # [-1, +1]
    sentiment_pos_ratio:    Mapped[float | None] = mapped_column(Float)
    sentiment_neg_ratio:    Mapped[float | None] = mapped_column(Float)
    sentiment_sample_size:  Mapped[int | None]   = mapped_column(Integer)
    sentiment_updated_at:   Mapped[datetime | None] = mapped_column(DateTime)
    
    # 관계
    nutrition_info:  Mapped["NutritionInfo"] = relationship(back_populates="restaurant", uselist=False)
    weather_score:   Mapped[list["WeatherLog"]] = relationship()
    meal_records:    Mapped[list["MealHistory"]] = relationship()
    visits:          Mapped[list["VisitHistory"]] = relationship()
    votes:           Mapped[list["Vote"]] = relationship()
    vetoes:          Mapped[list["Veto"]] = relationship()
    reviews:         Mapped[list["Review"]] = relationship()
```

**인덱스**:
- `idx_restaurant_location` (lat, lng) — 위치 기반 검색
- `idx_restaurant_active_distance` (is_active, distance_m) — 활성 + 가까운 순

## 5. 마이그레이션 / 변경 관리

### 5.1 현재 (MVP)
- `Base.metadata.create_all()` — idempotent 테이블 생성
- 기존 데이터 보존, 신규 컬럼 추가는 sentiment 케이스처럼 ALTER TABLE 직접 호출 (`ensure_schema()` 패턴)

### 5.2 향후 (PostgreSQL 이행 시)
- **Alembic** 도입 권장
- 마이그레이션 스크립트 자동 생성: `alembic revision --autogenerate -m "..."`
- CI에서 `alembic upgrade head` 실행

### 5.3 SQLite ↔ PostgreSQL 차이점
| 항목 | SQLite | PostgreSQL |
|---|---|---|
| ALTER TABLE 컬럼 추가 | ✅ | ✅ |
| ALTER TABLE 컬럼 변경 | ❌ (재생성 필요) | ✅ |
| BOOLEAN | INTEGER 0/1 | TRUE/FALSE |
| JSON 컬럼 | TEXT (직렬화) | JSONB |
| 동시 쓰기 | 단일 (file lock) | 다중 |
| 실시간 복제 | ❌ | streaming replication |

## 7. 데이터 무결성 / 일관성

### 7.1 외래키 제약
SQLite에서 FK는 기본적으로 OFF — `connection.py`의 connect listener로 활성화:
```python
@event.listens_for(Engine, "connect")
def set_sqlite_pragma(conn, _):
    cursor = conn.cursor()
    cursor.execute("PRAGMA foreign_keys=ON")
    cursor.close()
```

### 7.2 트랜잭션 패턴
```python
with get_session() as s:
    s.add(restaurant)
    s.add_all(reviews)
    # auto-commit if no exception, else rollback
```

### 7.3 동시성 (SQLite 한계)
- 단일 writer / 다중 reader (file lock)
- `WAL` 모드 활성화로 read 동시성 개선:
  ```python
  cursor.execute("PRAGMA journal_mode=WAL")
  ```
- 다중 워커가 필요해지면 PostgreSQL 이행

## 9. 분석 / 운영 쿼리 예시

### 9.1 인기 음식점 TOP 10 (최근 7일)
```sql
SELECT r.name, r.category, COUNT(DISTINCT v.user_id) as voters
FROM votes v JOIN restaurants r ON v.restaurant_id = r.id
WHERE v.vote_date >= date('now', '-7 days')
GROUP BY r.id, r.name, r.category
ORDER BY voters DESC LIMIT 10;
```

### 9.2 사용자별 단백질 평균 (이번 주)
```sql
SELECT user_id, AVG(protein) as avg_protein, COUNT(*) as meal_count
FROM meal_history
WHERE meal_date BETWEEN '2026-04-21' AND '2026-04-27'
GROUP BY user_id;
```

### 9.3 환각 의심 챗봇 응답 (NLP)
```sql
SELECT id, query, response, validation->>'$.mentioned_count' as mc
FROM chatbot_logs
WHERE json_extract(validation, '$.valid') = 0;
```
