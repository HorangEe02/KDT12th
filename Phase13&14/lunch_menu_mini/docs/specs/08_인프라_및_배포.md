# 08. 인프라 및 배포 명세

## 0. 개요

Mini는 **Docker Compose 기반의 4-서비스 오케스트레이션**으로 구동되며, GitHub Actions 3개 워크플로우로 CI/CD가 자동화되어 있습니다. 모든 외부 의존성(공공 API 키, Slack Webhook 등)은 `.env` 파일로 관리되며, 시크릿은 pre-commit `detect-secrets`로 git 커밋 차단됩니다.

### 0.1 핵심 사실
- **컨테이너**: `mini-ollama`, `mini-lunch-api`, `mini-nlp-api`, `mini-web` (총 4개) + `mini-caddy` (profile=proxy 활성 시)
- **이미지**: 직접 빌드 3개 (`mini/lunch-optimizer`, `mini/nlp-api`, `mini/dashboard-web`) + 외부 2개 (`ollama/ollama:latest`, `caddy:2-alpine`)
- **볼륨**: 7개 (mini-db, mini-logs, mini-chroma, mini-hf, mini-ollama-models, mini-caddy-data, mini-caddy-config)
- **네트워크**: `mini-net` (bridge)
- **호스트 OS**: macOS / Linux / Windows (WSL2)
- **이미지 합계**: ~4.3GB (lunch 603MB + nlp 3.43GB + web 282MB)
- **영속 데이터**: ~430MB (HF 캐시 423MB가 대부분)
- **운영 디렉터리** (2026-05-04~): `~/Downloads/lunch_menu_mini` (내장 SSD). 외장 SSD 운영 시기에 발생한 Docker bind mount stale(`mkdir /host_mnt/Volumes/...: file exists`) 이슈를 해소하기 위해 이동. 코드는 모두 상대경로 기반이라 named volume(mini-data 등)은 자동 재마운트되어 데이터 손실 없음. 마이그레이션 절차는 [`../RUN_LOCAL.md`](../RUN_LOCAL.md) "운영 변경 이력" 섹션 참조.

### 0.2 외부 노출 (데모용 임시 — Cloudflare Quick Tunnel)

- 프로덕션 권장: named tunnel 또는 도메인 + Let's Encrypt ([`../CLOUDFLARE_TUNNEL.md`](../CLOUDFLARE_TUNNEL.md))
- 데모 운영: `cloudflared tunnel --url https://localhost:443 --no-tls-verify` + Firebase Hosting ([`../QUICK_DEMO_DEPLOY.md`](../QUICK_DEMO_DEPLOY.md))
- 주의: `*.trycloudflare.com` 익명 quick tunnel은 24~72시간 후 호스트네임이 만료(NXDOMAIN). cloudflared 프로세스가 살아있어도 Cloudflare 엣지 재등록이 실패하므로 **새 URL 발급 → `./scripts/deploy_demo.sh "<NEW_URL>"`** 한 번으로 `.env.production` / 백엔드 CORS / Firebase Hosting 일괄 갱신.

## 1. Docker Compose 구성

### 1.1 `docker-compose.yml` 서비스 정의 (요약)

```yaml
services:
  ollama:
    image: ollama/ollama:latest
    container_name: mini-ollama
    ports: ["11434:11434"]
    volumes: ["mini-ollama-models:/root/.ollama"]
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:11434/api/tags"]
      interval: 30s
    networks: [mini-net]

  lunch-api:
    image: mini/lunch-optimizer:latest
    container_name: mini-lunch-api
    build:
      context: ./
      dockerfile: docker/Dockerfile.lunch
    ports: ["8000:8000"]
    env_file: .env
    volumes:
      - "mini-db:/app/lunch-optimizer/database"
      - "mini-logs:/app/logs"
    depends_on:
      ollama: { condition: service_healthy }
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/api/health"]
    networks: [mini-net]

  nlp-api:
    image: mini/nlp-api:latest
    container_name: mini-nlp-api
    build:
      context: ./
      dockerfile: docker/Dockerfile.nlp
    ports: ["8001:8001"]
    env_file: .env
    volumes:
      - "mini-db:/app/lunch-optimizer/database"
      - "mini-chroma:/app/chroma_store"
      - "mini-hf:/root/.cache/huggingface"
      - "mini-logs:/app/logs"
    depends_on:
      lunch-api: { condition: service_healthy }
      ollama:    { condition: service_healthy }
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8001/nlp/health"]
    networks: [mini-net]

  web:
    image: mini/dashboard-web:latest
    container_name: mini-web
    build:
      context: ./
      dockerfile: docker/Dockerfile.web
    ports: ["3000:3000"]
    environment:
      NEXT_PUBLIC_LUNCH_API: http://localhost:8000/api
      NEXT_PUBLIC_NLP_API:   http://localhost:8001
    depends_on:
      lunch-api: { condition: service_healthy }
      nlp-api:   { condition: service_healthy }
    networks: [mini-net]

volumes:
  mini-db:            { name: mini-db }
  mini-logs:          { name: mini-logs }
  mini-chroma:        { name: mini-chroma }
  mini-hf:            { name: mini-hf }
  mini-ollama-models: { name: mini-ollama-models }

networks:
  mini-net:           { name: mini-net }
```

### 1.2 Dependency 그래프
```
ollama (healthy) ─┬─→ lunch-api (healthy) ─┬─→ web (healthy)
                  └─→ nlp-api (healthy)  ──┘
```

| 서비스 | 검사 | 주기 |
|---|---|---|
| ollama | `GET /api/tags` | 30s |

## 2. Dockerfile 분석

### 2.1 `docker/Dockerfile.lunch` (Python 백엔드)
```dockerfile
FROM python:3.11-slim

WORKDIR /app
RUN apt-get update && apt-get install -y curl && rm -rf /var/lib/apt/lists/*

COPY lunch-optimizer/requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt

COPY lunch-optimizer/ ./lunch-optimizer/
COPY .env* ./

ENV PYTHONPATH=/app/lunch-optimizer
WORKDIR /app/lunch-optimizer

EXPOSE 8000
CMD ["uvicorn", "api.main:app", "--host", "0.0.0.0", "--port", "8000"]
```
**최종 사이즈**: ~603MB

### 2.2 `docker/Dockerfile.nlp` (PyTorch + transformers)
```dockerfile
FROM python:3.11

WORKDIR /app
RUN apt-get update && apt-get install -y \
    ca-certificates tzdata curl git build-essential \
    && rm -rf /var/lib/apt/lists/*

COPY NLP/nlp_mvp/requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt

# 비루트 사용자 생성 (보안)
RUN useradd -u 1001 -m appuser && chown -R appuser /app

COPY --chown=appuser NLP/ ./NLP/
COPY --chown=appuser lunch-optimizer/ ./lunch-optimizer/
COPY --chown=appuser .env* ./

USER appuser
ENV PYTHONPATH=/app/NLP:/app

EXPOSE 8001
CMD ["uvicorn", "nlp_mvp.api.main:app", "--host", "0.0.0.0", "--port", "8001"]
```
**최종 사이즈**: ~3.43GB (PyTorch CPU + transformers + chromadb 등)

### 2.3 `docker/Dockerfile.web` (Next.js standalone)
```dockerfile
# ---- Builder stage ----
FROM node:20-alpine AS builder

WORKDIR /app
COPY dashboard-web/package.json dashboard-web/package-lock.json ./
RUN npm ci

COPY dashboard-web/ .
RUN npm run build      # output: standalone

# ---- Runtime stage ----
FROM node:20-alpine

WORKDIR /app
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
COPY --from=builder /app/public ./public

EXPOSE 3000
CMD ["node", "server.js"]
```
**최종 사이즈**: ~282MB (multi-stage 덕분)

### 2.4 `docker/bootstrap.sh` (Ollama 모델 자동 pull)
```bash
#!/bin/sh
set -e

# 컨테이너 기동 후 ollama 헬스 대기
until curl -fs http://ollama:11434/api/tags >/dev/null 2>&1; do
    echo "Waiting for ollama..."
    sleep 2
done

echo "Pulling models..."
ollama pull qwen2.5:7b
ollama pull jhgan/ko-sroberta-multitask:latest 2>/dev/null || true

echo "Bootstrap complete."
```
- 첫 기동 시 ~5GB 다운로드 (qwen2.5:7b)
- `mini-ollama-models` 볼륨에 영속 → 재기동 시 즉시 사용

### 3.1 볼륨 별 책임
| 볼륨 | 마운트 경로 (컨테이너) | 용량 | 책임 |
|---|---|---|---|

| `mini-ollama-models` | `/root/.ollama` | ~5GB+ (모델 pull 후) | Ollama 모델 |

### 3.2 백업 / 복원 (개발용)
```bash
# 백업
for v in mini-db mini-chroma mini-logs mini-hf mini-ollama-models; do
    docker run --rm -v $v:/data -v $(pwd)/backups:/backup alpine \
        tar czf /backup/$v-$(date +%Y%m%d).tar.gz /data
done

# 복원
docker compose down
for v in mini-db mini-chroma mini-logs mini-hf mini-ollama-models; do
    docker volume create $v
    docker run --rm -v $v:/data -v $(pwd)/backups:/backup alpine \
        tar xzf /backup/$v-20260427.tar.gz -C /
done
docker compose up -d
```

## 6. 운영 절차

### 6.1 최초 기동
```bash
# 1. 환경 설정
cp .env.example .env
# .env 편집 — API 키 입력

# 2. 빌드 (~10–20분, 첫 빌드만)
docker compose build

# 3. 기동
docker compose up -d

# 4. Ollama 모델 pull (선택, ~5–10분)
docker exec mini-ollama ollama pull qwen2.5:7b

# 5. 헬스 확인
curl http://localhost:8000/api/health
curl http://localhost:8001/nlp/health
curl -I http://localhost:3000/

# 6. 데모 시드 (선택)
docker exec mini-lunch-api python -m scripts.seed_demo
```

### 6.2 일상 운영
```bash
# 로그 확인
docker compose logs -f lunch-api
docker compose logs -f nlp-api --tail 100

# 재시작
docker compose restart nlp-api

# 한 서비스만 재빌드
docker compose build web && docker compose up -d web

# 업데이트
git pull
docker compose build
docker compose up -d
```

### 6.3 정지 / 정리
```bash
# 일시 정지 (볼륨 보존)
docker compose stop

# 컨테이너 제거 (이미지·볼륨 보존)
docker compose down

# 볼륨까지 제거 (데이터 삭제 ⚠️)
docker compose down -v
```

### 6.4 트러블슈팅
| 증상 | 해결 |
|---|---|
| `nlp-api unhealthy` | `docker compose logs nlp-api` → HF 모델 로딩 대기 |
| `web` 빌드 시 TS 에러 | `dashboard-web/`에서 `npx tsc --noEmit` |
| Ollama 503 | `docker exec mini-ollama ollama list` 모델 확인 |
| DB lock | SQLite 단일 writer 한계 — WAL 활성화 또는 PostgreSQL 이행 |
| 디스크 부족 | `mini-hf` (423MB), `mini-ollama-models` (5GB+) prune 검토 |

## 7. 보안 / 네트워킹

### 7.1 컨테이너 격리
- 각 컨테이너는 `mini-net` 브릿지 네트워크 안에서만 서비스 디스커버리
- 호스트 노출 포트는 `3000, 8000, 8001, 11434`만
- Ollama는 컨테이너 외부에서 직접 접근 가능 (개발 편의) — 운영 환경에서는 11434 폐쇄 권장

### 7.2 보안 헤더 (FastAPI 미들웨어)
```python
@app.middleware("http")
async def add_security_headers(request, call_next):
    response = await call_next(request)
    response.headers["X-Content-Type-Options"] = "nosniff"
    response.headers["X-Frame-Options"] = "DENY"
    response.headers["Referrer-Policy"] = "strict-origin-when-cross-origin"
    response.headers["X-XSS-Protection"] = "1; mode=block"
    return response
```

### 7.3 CORS allowlist
```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.api.cors_origins,  # default: localhost:3000,5173
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

### 7.4 컨테이너 보안
- `nlp-api`만 비루트 사용자(`appuser` UID 1001) 실행 — PyTorch 다운로드 시 권한 격리
- 다른 컨테이너도 향후 비루트 마이그레이션 예정

## 9. 성능 / 부하 한계

### 9.1 단일 호스트 권장 사양
| 컴포넌트 | 최소 | 권장 |
|---|---|---|
| CPU | 4 cores | 8 cores |
| RAM | 8GB | 16GB |
| Disk | 20GB | 50GB SSD |
| OS | macOS / Ubuntu 22+ | Ubuntu 22.04 LTS |

### 9.2 동시 사용자 한계 (참고)
- **Web 서빙**: ~수십 동시 (Next.js standalone 단일 인스턴스)
- **Lunch API**: 단일 SQLite writer 한계 → 1초당 수십 RPS
- **NLP API**: Ollama 단일 GPU/CPU → 챗봇 동시 1–2명

### 9.3 스케일아웃 경로
1. **Web**: Next.js 인스턴스 다중화 + Nginx round-robin
2. **Lunch API**: Postgres 이행 + uvicorn workers ≥ 4
3. **NLP API**: 모델별 워커 분리 (sentiment 전용, chatbot 전용)
4. **Ollama**: GPU 가속 (NVIDIA Container Toolkit)
5. **Reverse Proxy**: Nginx / Traefik / Caddy

## 10. 클라우드 배포 옵션

### 10.1 단일 VM (간단)
- AWS Lightsail / DigitalOcean Droplet ($10–40/월)
- `docker-compose.yml` 그대로 배포
- 외부 접근: HTTPS는 Caddy reverse proxy로 자동 Let's Encrypt

### 10.2 Kubernetes (확장)
