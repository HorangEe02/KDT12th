# 02. 대시보드 7페이지 기능 명세

## 0. 개요

`dashboard-web/` (Next.js 16.2 + React 19)는 7개 페이지로 구성된 사용자 진입점입니다. 모든 페이지는 다음의 공통 패턴을 따릅니다:

- **데이터 페칭**: TanStack React Query 훅 (`src/lib/queries.ts`)
- **API 통신**: `apiFetchLunch<T>()` / `apiFetchNLP<T>()` (`src/lib/api.ts`)
- **타입**: `src/lib/types.ts` 도메인 모델
- **테마**: Warm Kitchen (Tailwind v4 + CSS variables, dark/light)
- **반응형**: Mobile-first, BottomNav(모바일) ↔ Sidebar(데스크톱)
- **인증/개인화**: localStorage `p11_*` 키 (이전 코드명 유지)

---

## 1. Dashboard (`/`)

### 1.1 목적
시스템 전반 KPI와 오늘의 추천을 1분 안에 파악할 수 있는 진입 화면.

### 1.2 UI 구성
- **헤더**: 서버 시간 클락 (1초 간격 업데이트)
- **KPI 카드 (4-col grid)**:
  1. 활성 음식점 수 (`/api/restaurants/stats`)
  2. 주간 식사 기록 (kcal>0 filter)
  3. 평균 감성 점수 (`/nlp/sentiment/top?limit=100` 평균)
  4. 챗봇 평균 지연 (`/nlp/chatbot/stats.avg_latency_ms`)
- **카테고리 분포 차트** (Recharts BarChart) — 카테고리별 음식점 수
- **Ollama 헬스 카드** — 모델 활성 상태, 10초 refetch
- **TODAY's TOP 5** — 4축 종합 점수 상위 5
- **For You 카드** — 개인화 ON 시 ML 추천

### 1.3 데이터 소스
```typescript
useRestaurants()         // /api/restaurants?limit=200 (60s refetch)
useLunchStats()          // /api/restaurants/stats
useWeatherCurrent()      // /api/weather/current (5min refetch)
useWeeklyNutrition(uid)  // /api/nutrition/weekly → fallback /trend
useSentimentTop(100)     // /nlp/sentiment/top
useChatbotStats()        // /nlp/chatbot/stats (15s refetch)
useNLPHealth()           // /nlp/health (10s refetch)
usePreferences()         // localStorage
```

### 1.4 핵심 로직 — 종합 점수 계산
```typescript
const scored = restaurants.map(r => ({
  ...r,
  composite: getCompositeScore(r, weather, weekly, TEAM)
}))
const top5 = scored.sort((a, b) => b.composite - a.composite).slice(0, 5)

if (prefs.enabled) {
  applyPersonalization(top5, prefs) // 가중치 [0, 1.5] 곱
}
```

### 1.5 모바일 처리
- KPI 그리드 wrap, 헤더 세로 스택
- 차트 single column

## 2. Discover (`/discover`)

### 2.1 목적
GPS 기반 위치 인지 음식점 탐색기. 거리·종합 점수·감성·평점·가격 기준 정렬, 카테고리 필터, Kakao Map 시각화.

### 2.2 UI 구성
- **위치 배지**: GPS / IP fallback 표시 (`useGeolocation`)
- **반경 슬라이더** (300m ~ 5km): 동적 limit (50/100/200/300)
- **모바일 탭**: Map / List
- **Kakao Map**: 사용자 핀 + 음식점 핀 + 반경 원
- **카테고리 필터 칩**: "전체" + 자동 추출 카테고리
- **정렬 드롭다운**: composite (기본) / sentiment / distance / rating / price
- **음식점 카드 리스트** (lg:col-3 grid): 이름, 카테고리, 거리, 점수, 감성 뱃지
- **DetailPanel** (데스크톱 col-2 / 모바일 bottom sheet): 6축 레이더, 감성 분포 (긍/중/부 %), 리뷰 수, 주소, 평점

### 2.3 데이터 소스
```typescript
useGeolocation()                    // GPS → IP → fallback
useNearbyRestaurants(lat,lng,r,n)   // /api/restaurants/nearby (5min cache, 100m grid 양자화)
useQueries([                        // 병렬 N개 — 음식점별 감성
  { queryKey: ['sentiment', id], queryFn: () => apiFetchNLP(`/nlp/sentiment/${id}`) }
])
```

### 2.4 위치 페일오버 (`useGeolocation.ts`)
1. **브라우저 GPS** (high-accuracy 8s timeout, fallback low-accuracy 5s)
2. **IP 기반** (`https://ipapi.co/json/`, 무료 1000회/일)
3. **하드코딩 fallback** (현재 미설정)

### 2.5 위치 캐시 키 양자화
```typescript
// 100m 격자로 lat/lng 반올림 → 사용자 이동 < 100m 시 재요청 회피
const keyLat = Math.round(lat * 1000) / 1000  // 0.001° ≈ 100m at equator
queryKey: ['nearby', keyLat, keyLng, radius]
```

## 3. Weather (`/weather`)

### 3.1 목적
실시간 기상 상태(기온·강수·미세먼지·하늘)에 맞춰 **무드 옵션**을 자동 생성하고, 무드별 메뉴 매칭 점수를 클라이언트에서 즉시 계산.

### 3.2 UI 구성
- **위치 셀렉터** (수동 override 가능: 대구 중구/동성로/강남역 등 7개 프리셋)
- **CurrentWeatherCard**: 기온/습도/먼지 등급/하늘/강수확률
- **WeatherTips**: 컨텍스트 가이드 ("오늘 쌀쌀합니다 — 따뜻한 국물 추천")
- **WeatherMoodSelector**: 이모지 버튼 그리드 (🏠/🍜/🔥/🧊/🍶/...)
- **무드 추천 카드**: 무드 선택 시 TOP5 (이모지+이름+카테고리+거리+이유+점수)
- **MenuFitnessChart**: 메뉴 유형별 평균 weather score
- **WeatherTopPicks**: 단일 weather score 정렬

### 3.3 무드 자동 생성 로직 (`buildMoodOptions`)
```typescript
// 비 + temp < 10 + 미세먼지 보통 → 다음 무드 활성화
if (rain > 50 || rainTypeStr !== '없음') {
  push('stay_close', 'soup_craving', 'rain_anju', 'rainy_walk')
}
if (temp < 10) push('warm_food', 'spicy_craving')
if (temp >= 28) push('cool_food', 'light_meal')
if (dust === '나쁨' || dust === '매우나쁨') push('indoor_only')
if (temp 17~25 && !rainy && dust 좋음) push('walk_enjoy')
```

### 3.4 무드 점수 (`calcMoodScore`)
| 무드 ID | 가중 |
|---|---|
| `stay_close` | dist≤100 +30, ≤200 +15, ≥300 -25 |
| `soup_craving` | menuType ∈ {국물,죽,탕} +35, 그 외 -10 |
| `warm_food` | 국물/죽/탕 +30, 면류 +20 |
| `cool_food` | 초밥/샐러드 +35 |
| `indoor_only` | indoor=true +25, 그 외 -30 |
| `walk_enjoy` | dist ≥ 300 +15 |

기본 50점에서 가산 후 `[0, 100]` 클램프.

### 3.5 가중치 일치 검증
**Important:** 클라이언트 `src/lib/scoring.ts` 가중치는 백엔드 `engine/recommender.py`와 일치:
```
distance: 0.3, weather: 0.2, nutrition: 0.2, team: 0.3
```

## 4. Nutrition (`/nutrition`)

### 4.1 목적
주간 칼로리·탄단지 추이 추적 + AI 코멘트 (NLG 리포트).

### 4.2 UI 구성
- **AI Comment Card**: `/nlp/reports/weekly/{userId}` 결과
- **에러 배너**: 영양 API 실패 시
- **Stat Cards Grid (4 cols)**:
  - 평균 칼로리 (🔥) — > 750kcal 시 빨강
  - 평균 단백질 (🥩) — < 20g 시 빨강
  - 균형 뱃지 (✅/⚠️/📊) — 단백질 비율 기반
  - 식사 기록 일수 (📅)
- **CalorieTrend** (Recharts LineChart, lazy-loaded): 7일 추이 + 목표선
- **MacroDonut** (PieChart): 탄단지 비율 + 목표 동심원
- **DailyBreakdown** (Stacked BarChart): 일별 매크로

### 4.3 단백질 비율 판정
```typescript
const pRatio = (protein / (protein + carbs + fat)) * 100
if (pRatio < 20)  → "단백질 부족" (error)
if (pRatio > 35)  → "단백질 과다" (tertiary)
else              → "균형 양호" (success)
```

### 4.4 NLG 리포트 페일백 체인
1. `useWeeklyReport(userId)` → `/nlp/reports/weekly/{uid}` (LLM 생성)
2. NLP 503 (warming up) → 지수 백오프 재시도 (최대 5회)
3. 최종 실패 → "주간 영양 데이터를 가져오는 중입니다" placeholder

### 4.5 사용자 ID 해석
```typescript
auth.id (string)
  → 숫자 추출
  → fallback: hash(user.id) % 100000 + 1
  → fallback: localStorage 'p11_user_id'
  → fallback: DEFAULT_USER_ID (env)
```

## 5. Vote (`/vote`)

### 5.1 목적
팀원 동시 투표로 점심 메뉴 결정. 결과 즉시 Slack 공유.

### 5.2 UI 구성
- **액션 바**: 랜덤 시뮬레이션 / 결과 확정 / 리셋 / 채팅 토글 / Slack 공유
- **VoterGrid** (col-3): 팀원별 아바타+이름+현재 투표
- **VoteResultBanner**: 우승자 발표 (이모지 셀러브레이션)
- **VoteResultsChart** (Horizontal Bar): 음식점별 득표 수
- **Visit History Card**: 최근 N일 방문이력
- **Team Chat Panel** (조건부): WebSocket 실시간 채팅

### 5.3 WebSocket 채팅 (`useTeamChat.ts`)
```typescript
// URL 변환: http://localhost:8000/api → ws://localhost:8000/ws/chat/{teamId}
ws.onopen     → connected=true, retries=0
ws.onmessage  → JSON.parse → ChatMessage append
ws.onclose    → 자동 재연결 (3s 백오프, 최대 5회)
```

### 5.4 Slack 통합
```typescript
POST /notify/slack {
  event: "vote_result",
  title: "오늘의 점심: 김치찌개 식당",
  body: "김치찌개 식당 — 5표 · 한식 · 120m",
  emoji: "🎉"
}
```
응답 상태: null → "sending" → "sent"/"failed"

### 5.5 투표 권한 정책
- 사용자는 자신의 투표만 변경 가능 (currentUser id 매칭)
- "랜덤 시뮬레이션"은 데모용으로 모든 멤버에 무작위 투표 일괄 적용

## 6. Concierge (`/concierge`)

### 6.1 목적
RAG + Function Calling 영양 상담 챗봇. 두 모드 토글:
- **RAG Mode**: SSE 토큰 스트리밍 + 컨텍스트 기반 자연어 응답
- **Tools Mode**: Phase 7 8개 함수 호출 → 실데이터 기반 액션

### 6.2 UI 구성
- **헤더**: RAG 컨텍스트 요약 (meal_history N건, nutrition_info N건, restaurants N건) + 모드 토글 + Reset
- **Health/Warming 배너**: NLP 503 시 retry-after 카운트다운
- **환각 경고 배너**: `validation.mentioned_count === 0 && recommendations.length > 0`
- **메시지 스트림**: 좌(어시스턴트) / 우(사용자) 정렬, 자동 스크롤
- **Input Bar** (sticky bottom): 텍스트 입력 + Send/Stop

### 6.3 SSE 스트리밍 (`apiStreamSSENLP`)
```typescript
POST /nlp/chatbot/chat/stream { user_id, query }

// 프레임 타입별 콜백
data: {"type":"meta","context_summary":{...}}        → onMeta
data: {"type":"token","text":"안녕"}                  → onToken (UI 즉시 갱신)
data: {"type":"final","recommendations":[...],"validation":{...},"latency_ms":450}
                                                      → onFinal
data: [DONE]                                          → onDone
```
AbortController로 사용자가 도중에 중단 가능.

### 6.4 Tool Calling 모드
```typescript
POST /nlp/chatbot/chat/tools {
  user_id, query, temperature: 0.2, max_iterations: 3
}
→ ToolChatOut {
    response,        // 최종 답변
    tool_calls[],    // 실행된 도구 + 인자
    tool_results[],  // HTTP 응답 모음
    iterations,      // 반복 횟수
    latency_ms,
    fallback_used    // heuristic router 사용 여부
}
```

## 8. 공통 인프라 레이어

### 8.1 `src/lib/api.ts`
```typescript
LUNCH_API = NEXT_PUBLIC_LUNCH_API ?? "http://localhost:8000/api"
NLP_API   = NEXT_PUBLIC_NLP_API   ?? "http://localhost:8001"

apiFetchLunch<T>(path, init?)  // /api/* → JSON or throw
apiFetchNLP<T>(path, init?)    // /nlp/* → JSON or throw NLPPendingError(503)
apiStreamSSENLP(path, body, cbs, signal?)  // SSE 프레임 라우팅
```

### 8.2 `src/lib/queries.ts` (TanStack hooks)
| Hook | 캐시 / 정책 |
|---|---|
| `useRestaurants` | 60s refetch + mock fallback + placeholderData |
| `useNearbyRestaurants` | 100m 격자 양자화 키, 5min staleTime, no refetch on focus |
| `useWeatherCurrent` | 5min refetch + mock fallback |
| `useNLPHealth` | 10s refetch + warming retry |
| `useSentimentTop` | retry: false |
| `useChatbotStats` | 15s refetch |
| `useWeeklyReport` | warming retry (지수 백오프, max 5회) |
| `useTeamMembers` | 30s staleTime, retry: false, mock fallback |

### 8.3 `src/lib/preferences.ts` — 개인화 다중자
```typescript
personalizedMultiplier(restaurant, prefs) ∈ [0, 1.5]
+0.2  if favoriteCategory
-0.3  if dislikedCategory  
-0.15 if exceeds maxPrice (soft)
-recencyPenalty * (visits/20)  if visited recently
×0    if hasAllergenConflict (substring match)
```

### 8.4 `src/lib/auth.ts`
```typescript
loadCurrentUser()         // localStorage 'p11_current_user'
saveCurrentUser(u)        // → 'p11_auth_updated' custom event
login(id, name, ...)      // POST /api/users (idempotent)
logout()                  // clear localStorage
syncPreferencesToBackend  // PATCH /users/{id}/preferences
pullPreferencesFromBackend // GET /users/{id}
```

### 8.5 디자인 시스템 (`globals.css`)
- **CSS Variables**: `--bg, --s1, --s2, --s3, --primary, --secondary, --tertiary, --txt-1~3, --outline`

## 10. 성능 최적화

1. **코드 스플리팅**: Recharts (~90kB gzip) lazy import → Nutrition/Weather/Vote 페이지에서만 로드
2. **Map dynamic import** (`ssr: false`) — Leaflet 초기 번들 제외
3. **useMemo**: 정렬/필터/스코어링 결과 캐싱
4. **Skeleton UI**: 데이터 로딩 중 placeholder
5. **위치 캐시**: useGeolocation 결과 60s GPS / 5min IP

## 11. 알려진 제약사항

| 항목 | 제약 | 완화 |
|---|---|---|
| 오프라인 | Service Worker 미구현 | mock fallback 모든 주요 쿼리 |

| NLP Warming | 모델 로딩 ~30초 | UI 배너 + retry-after |
