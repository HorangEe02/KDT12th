# 03. 백엔드 데이터 파이프라인 및 추천 엔진

## 0. 개요

`lunch-optimizer/` 디렉터리는 Mini의 데이터 수집·정제·저장·추천 백엔드를 구성합니다. **4개의 외부 공공 API Collector**가 APScheduler로 자동 실행되며, **추천 엔진**은 4축 가중 스코어링으로 음식점을 정렬합니다.

```
[외부 API] → [Collector] → [Transformer] → [Loader/SQLAlchemy] → [DB]
                                                                  ↓
[FastAPI 45 endpoints] ← [LunchRecommender (4축 스코어링)] ←──────┘
```

### 0.1 디렉터리 구조
```
lunch-optimizer/
├── api/              # FastAPI 라우팅 (main.py 3,240 라인)
├── engine/           # 추천 엔진 (recommender.py)
├── pipeline/
│   ├── collectors/   # 4개 수집기 (restaurant/weather/nutrition/air_quality)
│   ├── transformers/ # 점수 계산 (distance_scorer.py 등)
│   ├── loaders/      # SQLAlchemy 영속화
│   ├── utils/        # 좌표 변환 등 유틸
│   └── scheduler.py  # APScheduler 진입점
├── database/         # ORM 모델 + 연결 (11+ 테이블)
├── config/           # settings.py (.env 로딩)
├── scripts/          # seed_demo.py 등
└── tests/            # pytest
```

## 1. Collector 1 — Restaurant (카카오맵)

### 1.1 외부 API
- **Provider**: Kakao Local Search v2
- **Base URL**: `https://dapi.kakao.com`
- **Endpoints**:
  - `/v2/local/search/category.json` (카테고리 기반)
  - `/v2/local/search/keyword.json` (키워드 기반)
- **인증**: `Authorization: KakaoAK {KAKAO_REST_API_KEY}` + `KA: sdk/2.7.4 ...` (KA 헤더는 2025+ 필수)

### 1.2 Collector 클래스
```python
# pipeline/collectors/restaurant_collector.py
RestaurantCollector(
    lat: float = 37.5665,    # 사무실 위도 (default 종로구)
    lng: float = 126.9780,   # 사무실 경도
    radius_m: int = 500,     # 검색 반경
)
```

### 1.3 출력 스키마 (Kakao 원본)
```json
{
  "id": "kakao_place_id",
  "place_name": "김치찌개 명가",
  "category_name": "음식점 > 한식 > 찌개,전골",
  "phone": "02-...",
  "address_name": "...",
  "x": "126.978",   // longitude
  "y": "37.5665",   // latitude
  "place_url": "..."
}
```

### 1.4 정책
| 항목 | 값 |
|---|---|
| MAX_RETRIES | 3 |
| 재시도 백오프 | exponential, 429 시 Retry-After 준수 |
| TIMEOUT | 10.0 sec |
| SLEEP_BETWEEN_REQUESTS | 0.3 sec |
| PAGE_SIZE | 15 (Kakao 한계) |
| MAX_PAGES | 45 |
| 일일 쿼터 | 100,000 (DailyQuotaTracker) |

### 1.5 변환 (transformers/distance_scorer.py)
- `haversine_distance(lat1, lng1, lat2, lng2) → meters`
- `compute_distance_score(distance_m) → 0~100`:
  - ≤ 100m → 100
  - ≤ 200m → 85
  - ≤ 300m → 70
  - ≤ 400m → 50
  - > 400m → 30

### 1.6 스케줄
APScheduler CronTrigger `hour=10, minute=0` 매일 (Asia/Seoul)

### 2.1 외부 API
- **Provider**: KMA (기상청) 단기예보 API via data.go.kr
- **Base URL**: `http://apis.data.go.kr/1360000/VilageFcstInfoService_2.0`
- **Endpoints**:

### 2.2 출력 스키마
```python
{
    "temp": float,        # 기온 (°C)
    "humidity": int,      # 습도 (%)
    "rain_type": int,     # 강수형태 코드 (0=없음, 1=비, 2=비/눈, 3=눈, 4=소나기)

    "wind_speed": float,  # 풍속 (m/s)
    "sky": int,           # 1=맑음, 3=구름많음, 4=흐림
    "pop": int,           # 강수확률 (%)
```

### 2.4 스케줄
- 시간 단위: CronTrigger `minute=5` (매시 :05)
- 일 단위: 09:30 풀 갱신

### 3.1 외부 API
- **Provider**: 식품안전나라 영양정보 DB (Service ID `I2790`)
- **Base URL**: `https://openapi.foodsafetykorea.go.kr/api`

### 3.2 메서드

### 3.3 출력 스키마 (100g 기준)
| 필드 | 의미 |
|---|---|
| FOOD_NM | 식품명 |
| FOOD_CD | 식품코드 |
| SERVING_SIZE | 제공량 (g, 기본 100g) |
| NUTR_CONT1 | 열량 (kcal) |
| NUTR_CONT2 | 탄수화물 (g) |
| NUTR_CONT3 | 단백질 (g) |
| NUTR_CONT4 | 지방 (g) |
| NUTR_CONT5 | 당류 (g) |
| NUTR_CONT6 | 나트륨 (mg) |

### 3.4 데이터 정합성

### 3.5 정책
- MAX_RETRIES = 3, _BULK_SLEEP_SEC = 0.5
- 호출당 TIMEOUT = 10.0

## 5. 추천 엔진 (`engine/recommender.py`)

### 5.1 4축 점수
```python
DEFAULT_WEIGHTS = {
    "distance": 0.3,    # 거리 (가까울수록 높음)
    "weather": 0.2,     # 날씨 적합도
    "nutrition": 0.2,   # 영양 균형
    "team": 0.3,        # 팀 선호 (투표 + 방문 빈도)
}

NO_VOTE_WEIGHTS = {     # 투표 데이터 부재 시
    "distance": 0.4,
    "weather": 0.3,
    "nutrition": 0.3,
    "team": 0.0,
}
```

### 5.2 컴포지트 점수 계산
```python
def composite_score(restaurant, ctx) -> float:
    d = compute_distance_score(restaurant.distance_m)        # 0~100
    w = WeatherMenuScorer.score(restaurant, ctx.weather)     # 0~100
    n = NutritionRecommendScorer.score(restaurant, ctx.user_weekly)
    t = TeamRecommendScorer.score(restaurant, ctx.team_history)
    
    weights = DEFAULT_WEIGHTS if has_votes(ctx) else NO_VOTE_WEIGHTS
    return d*weights['distance'] + w*weights['weather'] \
         + n*weights['nutrition'] + t*weights['team']
```

### 5.3 4개 Scorer 상세

#### 5.3.1 Distance Score
거리(m) → 단계 함수 (위 §1.5 참고)

#### 5.3.2 WeatherMenuScorer
- 기온·강수확률·미세먼지·하늘 상태 + 음식 menuType 조합
- 예: temp < 5 + 국물/탕 → +30 보너스
- 예: dust 나쁨 + indoor=true → +15

#### 5.3.3 NutritionRecommendScorer
주간 매크로 분석 → 부족한 영양소 보강 메뉴 가산
```
avg_protein < 25g && r.protein ≥ 30g  → +20
avg_fat > 30g && r.fat ≤ 15g          → +20
r.calories ∈ [400, 700]               → +10  (건강 적정 범위)
```
플래그: 고나트륨/고당류 음식 감점

#### 5.3.4 TeamRecommendScorer
- **투표 가중**: 최근 우승 빈도 (시간 감쇠)
- **방문 빈도**: 자주 가는 곳 가산, 단 < 3일 내 방문 시 freshness 감점
- **팀 거부 카테고리**: dislike_categories 매칭 시 강력 감점

### 5.4 엣지 케이스 처리
| 시나리오 | 처리 |
|---|---|
| 날씨 데이터 없음 | 중립값 50 |
| 영양 기록 < 3건 | `NutritionDiagnostic`이 `data_warning` 발행 |
| 활성 음식점 0개 | 빈 배열 + 로그 경고 |
| 추천 캐시 만료 | 60s TTL 후 재계산 |

### 5.5 NLP Sentiment Patch (선택)
`NLP/nlp_mvp/integration/scoring_patch.py` (구현 예정 위치)에서 `sentiment_score` 컬럼을 1개 axis로 추가하는 monkey patch.
- 기본 가중: 0.15~0.20 추가 axis
- ON 시 기존 4축 합 0.85, sentiment 0.15

## 6. 파이프라인 스케줄러 (`pipeline/scheduler.py`)

### 6.1 BlockingScheduler 잡 정의
```python

# 일 단위 (09:30) — 음식점 + 영양 풀 갱신

scheduler.add_job(restaurant_pipeline, CronTrigger(hour=10, minute=0))

```


## 7. 데이터베이스 접근 패턴

### 7.1 Singleton Engine + Session 컨텍스트
```python
# database/connection.py
@lru_cache
def get_engine() -> Engine:
    return create_engine(
        settings.db.url,        # default: sqlite:///./lunch-optimizer/database/mini.db
        echo=settings.db.echo,
        future=True,
        connect_args={"check_same_thread": False},  # SQLite 전용
    )

@contextmanager
def get_session() -> Iterator[Session]:
    session = sessionmaker(bind=get_engine())()
    try:
        yield session
        session.commit()
    except Exception:
        session.rollback()
        raise
    finally:
        session.close()
```

### 7.2 스키마 초기화
```python
def init_schema() -> None:
    """Idempotent — 기존 테이블 보존, 누락만 생성"""
    Base.metadata.create_all(get_engine())
```

FastAPI lifespan에서 startup 시 호출.

### 7.3 SQLite ↔ PostgreSQL 이행
- `DB_URL` 변경만으로 마이그레이션 (예: `postgresql://user:pass@host/db`)
- `connect_args` 분기 필요 (`check_same_thread`는 SQLite 전용)
- Alembic 미통합 — 향후 도입 시 마이그레이션 자동화 가능

## 9. 에러 처리 / 폴백 전략

### 9.1 Collector 레벨
| 시나리오 | 동작 |
|---|---|
| HTTP 4xx | 즉시 실패, 로그 + 스킵 |
| HTTP 5xx / Timeout | 지수 백오프 재시도 (max 3회) |
| 429 Rate Limit | Retry-After 헤더 준수 |
| Malformed XML | None 반환, 로그 경고 |
| 일일 쿼터 초과 | DailyQuotaTracker가 호출 거부 |

### 9.2 Recommender 레벨
- 캐싱: in-memory 60s TTL
- 결과 < 1개 시 mock 데이터 반환 (대시보드 빈 상태 회피)

### 9.3 API 레벨
- FastAPI exception handler → 일관된 `{"error": ..., "detail": ...}` JSON
- 보안 헤더 미들웨어 (모든 응답에 X-Content-Type-Options 등)
