# 소주제 5: Streamlit 대시보드 통합 및 시스템 배포 — 결과 보고서

> **목적**: 소주제 1~4에서 구축한 전처리 파이프라인, ML/DL/AD 모델, 교차 도메인/합성 강건성 검증 결과를 **2-모드 인터랙티브 대시보드**로 통합하여, 비전문가도 결함 검수 시스템을 실시간으로 체험할 수 있는 최종 산출물을 완성한다.

## 1. 기(起) — 왜 대시보드가 필요한가?

### 1.1 노트북의 한계

소주제 1~4의 결과는 모두 Jupyter 노트북(12개)에 있다. 하지만 노트북은 다음과 같은 한계가 있다:

| 노트북의 한계 | 대시보드의 해결 |
|-------------|---------------|
| 코드를 순차적으로 실행해야 함 | **버튼 클릭으로 즉시 결과 확인** |
| Python 지식이 필요 | **비전문가도 사용 가능** |
| 파라미터 변경 시 코드 수정 필요 | **슬라이더/드롭다운으로 실시간 조정** |
| 결과가 셀 출력으로만 표시 | **시각적 대시보드로 한눈에 파악** |
| ML·DL·AD 결과가 별도 노트북에 분산 | **2-모드 9페이지로 모든 결과를 통합** |

> **비유**: 노트북이 "레시피를 보면서 직접 요리하는 것"이라면, 대시보드는 **"레스토랑에서 메뉴판을 보고 주문하는 것"**이다.

### 1.2 핵심 용어 정리

| 용어 | 설명 | 비유 |
|------|------|------|
| **Streamlit** | Python 코드만으로 웹 대시보드를 만들 수 있는 프레임워크 | 코드를 웹사이트로 바꿔주는 마법 도구 |
| **모드(Mode)** | 대시보드의 사용 목적에 따른 전환 (시뮬레이터 vs 인사이트) | TV 채널 전환 |
| **페이지(Page)** | 각 모드 안에서 선택하는 개별 기능 화면 | 채널 안의 프로그램 |
| **사이드바(Sidebar)** | 화면 왼쪽에 고정된 Control Panel | 리모컨 |
| **세션 상태(Session State)** | 페이지 간 설정이 공유·유지되는 저장소 | 브라우저의 기억력 |
| **캐시(Cache)** | 한 번 로드한 모델/데이터를 메모리에 저장하여 재사용 | 자주 쓰는 도구를 책상 위에 꺼내놓기 |

## 2. 승(承) — 대시보드 아키텍처 설계

### 2.1 2-모드 체제 (Q1 업데이트)

기존 8탭 구조를 **2-모드 + 9페이지 + 사이드바 Control Panel** 구조로 전면 재설계하였다:

```
┌────────────────────────────────────────────────────────────────────┐
│  Control Panel (사이드바)                                           │
│  ├── 모드 선택: 시뮬레이터 / 인사이트 (라디오)                      │
│  ├── 페이지 선택: selectbox (모드별 다른 목록)                      │
│  ├── 테마 설정: 자동(야간) / 주간 모드 / 야간 모드                  │
│  └── 데이터셋 통계: Severstal 150,816 패치 / NEU-DET 1,440장       │
├────────────────────────────────────────────────────────────────────┤
│  본문 영역 (선택된 페이지만 렌더링)                                  │
│  ┌─ 시뮬레이터 모드 (4페이지) ──────────────────────────┐          │
│  │  실시간 검수 / 배치 분석 / 파이프라인 설정 / 시스템 정보  │          │
│  └──────────────────────────────────────────────────────┘          │
│  ┌─ 인사이트 모드 (5페이지) ────────────────────────────┐          │
│  │  전처리 분석 / ML vs DL 비교 / 이상탐지 분석 /          │          │
│  │  도메인 일반화 분석 / 통합 비교                          │          │
│  └──────────────────────────────────────────────────────┘          │
└────────────────────────────────────────────────────────────────────┘
```

### 3.3 2-Stage 파이프라인 라이브 데모

실시간 검수 페이지에서 Severstal 2-Stage 파이프라인 라이브 데모:

```
[사용자가 이미지 선택/업로드]
    ↓
[Stage 1] AE 이상 탐지 — 정상/비정상 판정
    ↓
    "비정상" 판정 시
    ↓
[Stage 2 자동 실행] ResNet-18 FT 4-class 분류
    ↓
"PS (Pitted Surface), 신뢰도 95.2%, 처리 시간 12ms"
```

정상 이미지인 경우:
```
[Stage 1] "정상 판정 → Stage 2 불필요 → 통과 ✅"
```

결함 4종: PS(점상 결함) / LS(선형 결함) / SS(변색 결함) / RD(압흔 결함)

이 **라이브 데모**가 발표에서 가장 임팩트 있는 시연 포인트이다.

### 3.4 파이프라인 설정 → 실시간 검수 연동 (Q4)

```python
# tab_settings.py에서 설정 저장
st.session_state["cfg_stage1_model"] = "DL: ResNet-18 FT"
st.session_state["cfg_stage2_model"] = "DL: ResNet-18 FT"
st.session_state["cfg_anomaly"] = True
st.session_state["cfg_anomaly_threshold"] = 0.002

# tab_realtime.py에서 설정 읽기
default_model = st.session_state.get("cfg_stage1_model", "DL: ResNet-18 FT")
```

설정 탭에서 모델을 변경하면, 실시간 검수 탭의 selectbox 기본값이 자동으로 반영된다.

### 3.5 importlib 기반 모듈 로딩

**문제**: `from streamlit.tabs.tab_deep_learning import ...` → Python 설치된 `streamlit` 패키지와 로컬 `streamlit/` 디렉토리를 혼동

**해결**: `importlib.util`로 파일 경로를 직접 지정하여 로드

```python
spec = importlib.util.spec_from_file_location("tab_deep_learning",
       os.path.join(tabs_dir, "tab_deep_learning.py"))
mod = importlib.util.module_from_spec(spec)
spec.loader.exec_module(mod)
```

## 4. 결(結) — 대시보드의 가치와 결론

### 4.1 대시보드의 3가지 역할

| 역할 | 대상 | 가치 |
|------|------|------|
| **발표 도구** | 심사위원, 교수 | 슬라이드 대신 실시간 시연 → 차별화 |
| **포트폴리오** | 채용 담당자 | "모델만 만든 게 아니라 배포까지 완성" 증명 |
| **실무 프로토타입** | 공장 QA 엔지니어 | 실제 업무에 적용 가능한 인터페이스 |

### 4.2 기술 스펙 요약

| 항목 | 수치 |
|------|------|
| 총 코드 라인 | **~4,210줄** (13개 .py: app.py + 12 모듈) |
| 구조 | **2-모드** (시뮬레이터 4페이지 + 인사이트 5페이지) |
| 로드하는 모델 | **10+개** (ML 7 + DL 2 + AE 1) |
| 표시하는 시각화 | **48개** 저장 PNG + 다수의 동적 차트 |
| info-box (설명) | **20+개** |
| CSS 변수 | **22개** (주간/야간 각각) |
| 캐시 함수 | **4개** (`@st.cache_resource`) |
| 테마 모드 | **3가지** (자동/주간/야간) |
| session_state 연동 | **4개 키** (Stage 1/2 모델, 이상탐지 설정) |

### 4.5 소주제 5의 최종 결론

1. **2-모드 체제로 사용 목적 분리 (Q1)**: 기존 8탭 구조에서 **시뮬레이터(실무용 4페이지) + 인사이트(분석용 5페이지)**로 재구성하여, 사용자 역할에 맞는 인터페이스를 제공.

2. **파이프라인 설정 연동 (Q4)**: session_state 기반으로 설정 탭의 모델 선택·임계값이 실시간 검수에 자동 반영. 탭 간 설정이 끊기지 않는 일관된 UX.

3. **도메인 일반화 분석 명칭 정비 (Q2)**: "교차 도메인 검증"을 **"도메인 일반화 분석"**으로 통일. 도메인 전이(NB11) + 합성 강건성(NB11b) 이중 검증 결과를 통합 시각화.

4. **2-Stage 파이프라인 라이브 데모가 킬러 기능**: AE(Recall 96%) → ResNet-18 FT(Acc 86.01%)가 순차 실행되는 모습은 발표에서 **"이 시스템이 실제로 동작한다"**는 것을 가장 강력하게 증명.

5. **~4,210줄의 프로덕션 품질 코드**: 13개 Python 모듈, 캐시 최적화, 에러 핸들링, 반응형 레이아웃, 주간/야간 테마 시스템 등 실무 수준의 웹 애플리케이션 개발 역량을 증명.

6. **전체 프로젝트의 마침표**: 소주제 1(전처리) → 2(필터링) → 3(특징 추출) → 4(분류+검증) → **5(대시보드)**로 이어지는 완전한 End-to-End 파이프라인의 최종 산출물.
