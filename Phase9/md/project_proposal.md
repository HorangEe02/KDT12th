## 1. 프로젝트 개요

### 1.1 프로젝트 배경

제조 공정에서 발생하는 금속 표면 결함(균열, 스크래치, 개재물 등)은 제품 품질과 안전성에 직결되는 핵심 요소이다. 기존의 육안 검사 방식은 검사자의 피로도, 주관적 판단, 처리 속도 한계 등의 문제를 안고 있으며, 고가의 산업용 비전 장비는 중소기업에 부담이 된다.

본 프로젝트는 **OpenCV 기반 이미지 전처리**와 **Scikit-learn 기반 머신러닝 분류 모델**을 결합하여, 금속 표면의 6종 결함을 자동으로 분류하는 하이브리드 검수 시스템을 구축한다. 전통적 컴퓨터 비전 기법의 실질적 효과를 정량적으로 검증하고, 저비용·고효율의 품질 검사 파이프라인을 제안하는 것을 목표로 한다.

### 1.2 프로젝트 목표

| 구분 | 목표 |
|------|------|
| **핵심 목표** | NEU 금속 표면 결함 데이터셋을 활용하여 6종 결함 자동 분류 시스템 구축 |
| **기술 목표** | OpenCV 전처리 파이프라인 설계 및 전처리 전/후 성능 차이 정량 비교 |
| **분석 목표** | 결함 유형별 오분류 패턴 분석 및 제조업 맥락의 평가 지표(Recall 중심) 해석 |
| **확장 목표** | 로컬(M4 Pro) 환경에서의 엣지 컴퓨팅 적용 가능성 확인 |

### 1.3 기대 효과

- **교육적 효과**: 강의 1~4차시의 OpenCV 핵심 기법(ROI, 필터링, 에지 검출, ML 모델링)을 하나의 파이프라인으로 통합 실습
- **실무적 효과**: 제조업 품질 검사 자동화의 기초 파이프라인 경험 축적
- **포트폴리오 효과**: 전통 CV+ML 기반 제조 결함 분류 → 향후 딥러닝 확장 가능한 기반 프로젝트 확보

## 2. 데이터셋

### 2.1 메인 데이터셋: NEU Metal Surface Defects Dataset

| 항목 | 내용 |
|------|------|
| **출처** | Kaggle — NEU Surface Defect Database |
| **링크** | https://www.kaggle.com/datasets/kaustubhdikshit/neu-surface-defect-database |
| **원본** | 동북대학교(Northeastern University, China) |
| **이미지 수** | 1,800장 (6클래스 × 300장) |
| **이미지 크기** | 200 × 200 픽셀 |
| **색상** | 그레이스케일 |
| **포맷** | BMP / JPEG |

### 2.2 결함 유형 (6클래스)

| 클래스 | 영문명 | 설명 | 시각적 특징 |
|--------|--------|------|-------------|
| 1 | Crazing | 균열 | 그물망 형태의 미세 균열 패턴 |
| 2 | Inclusion | 개재물 | 표면에 이물질이 포함된 불규칙 형태 |
| 3 | Patches | 패치 | 불균일한 색상 영역 |
| 4 | Pitted Surface | 구멍 | 점 형태의 표면 함몰 |
| 5 | Rolled-in Scale | 압연 스케일 | 압연 과정에서 말려 들어간 산화물 |
| 6 | Scratches | 스크래치 | 선형의 긁힘 자국 |

### 2.3 데이터셋 선정 이유

1. **OpenCV 전처리 효과 극대화**: 그레이스케일 이미지이므로 필터링, 에지 검출, 히스토그램 처리 등의 효과가 직접적으로 드러남
2. **다중 분류 과제**: 6클래스 분류로 Scikit-learn의 다양한 분류 알고리즘을 비교 실험할 수 있음
3. **제조업 도메인 적합성**: 금속 표면 결함이라는 주제가 자동차·반도체·철강 등 제조업 전반과 직결
4. **적절한 데이터 규모**: 1,800장은 Colab이나 로컬 환경에서 부담 없이 처리 가능하면서도, ML 모델 학습에 충분한 양

## 3. 핵심 소주제 (강의 커리큘럼 연계)

### 소주제 ① — 정밀 검사를 위한 이미지 정렬 및 ROI 추출

> **연계 차시**: 1~2차시 (픽셀/채널 구조, 색공간, ROI)

- **목표**: 입력 이미지의 기하학적 보정 및 검사 대상 영역 정확 추출
- **핵심 기법**:
  - 이미지 회전 보정 (affine transformation)
  - ROI(Region of Interest) 추출 및 리사이징
  - 히스토그램 균등화를 통한 밝기/대비 정규화
- **적용 방안**: NEU 데이터는 이미 정렬된 상태이므로, 회전 보정 데모 코드를 별도 작성하여 "실환경 적용 시 필요한 전처리"로 제시

### 소주제 ② — 결함 특징 극대화를 위한 필터링 및 샤프닝

> **연계 차시**: 3차시 (이미지 필터링과 변환)

- **목표**: 결함의 시각적 특징을 강조하고 노이즈를 제거하여 검수 정확도 향상
- **핵심 기법**:
  - 가우시안 블러 (Gaussian Blur) — 노이즈 제거
  - 언샤프 마스크 (Unsharp Masking) — 결함 경계 샤프닝
  - 적응형 히스토그램 균등화 (CLAHE) — 저대비 결함 강조
  - 모폴로지 연산 (Morphological Operations) — 미세 결함 강조/제거
- **실험 설계**: 전처리 조합별(원본 / 블러만 / 샤프닝만 / 블러+샤프닝 / CLAHE) 결과를 시각적으로 비교

### 소주제 ③ — 에지 검출 및 윤곽선 기반 특징 분석

> **연계 차시**: 4차시 (임계값 처리, 에지 검출, 윤곽선 분석)

- **목표**: 결함의 형태적 특징을 에지/윤곽선으로 추출하여 특징 벡터에 반영
- **핵심 기법**:
  - Canny 에지 검출 — 결함 경계선 추출
  - 윤곽선(Contour) 검출 및 면적/둘레 계산
  - 에지 밀도(Edge Density) 계산 — 결함 유형별 에지 분포 차이 정량화
- **분석 포인트**: 결함 유형별 에지 밀도 분포를 비교하여, 어떤 결함이 에지 기반 특징으로 잘 구분되는지 확인

### 소주제 ④ — 하이브리드 결함 분류 모델링

> **연계 차시**: 3~4차시 (CV기반 ML 모델 저장/로딩, 분류 모델 적용)

- **목표**: OpenCV 전처리 + 특징 추출 결과를 ML 모델에 입력하여 6종 결함 자동 분류
- **핵심 기법**:
  - 특징 추출: HOG (Histogram of Oriented Gradients), LBP (Local Binary Pattern), 픽셀 통계값
  - 분류 모델: SVM (RBF 커널), Random Forest, KNN
  - 모델 평가: Confusion Matrix, 클래스별 Precision/Recall/F1, ROC Curve (OvR)
  - 모델 저장/로딩: joblib을 활용한 학습 모델 직렬화
- **핵심 실험**: 전처리 전/후, 특징 조합별 성능 비교 (아래 표 참고)

| 실험 조건 | 특징 | 모델 | 비교 목적 |
|-----------|------|------|-----------|
| 원본 이미지 | HOG만 | SVM, RF, KNN | 베이스라인 |
| 전처리 적용 | HOG만 | SVM, RF, KNN | 전처리 효과 측정 |
| 전처리 적용 | HOG + LBP | SVM, RF, KNN | 특징 조합 효과 |
| 전처리 적용 | HOG + LBP + 통계 | SVM, RF, KNN | 최적 특징 조합 탐색 |

## 8. 핵심 분석 전략

### 8.1 전처리 효과 정량 비교

본 프로젝트의 가장 중요한 분석 포인트는 **"OpenCV 전처리가 ML 분류 성능에 미치는 실질적 효과"**를 정량적으로 증명하는 것이다.

**비교 실험 설계**:

| 조건 | 전처리 | 특징 | 기대 효과 |
|------|--------|------|-----------|
| Baseline | 없음 | HOG | 전처리 없는 기준 성능 |
| Exp-1 | 가우시안 블러 | HOG | 노이즈 제거 효과 |
| Exp-2 | 블러 + 샤프닝 | HOG | 결함 경계 강조 효과 |
| Exp-3 | 블러 + CLAHE | HOG | 저대비 결함 강조 효과 |
| Exp-4 | 블러 + 샤프닝 | HOG + LBP + 통계 | 최적 조합 탐색 |

### 8.2 제조업 맥락의 평가 지표 해석

일반적인 분류 문제와 달리, 제조업 품질 검사에서는 **오분류의 방향**이 중요하다.

- **False Negative (불량 → 정상 오판)**: 불량품이 출하되어 고객 클레임, 리콜 발생 → **치명적**
- **False Positive (정상 → 불량 오판)**: 정상 제품이 폐기되어 생산성 손실 → **비용 손실**

따라서 본 프로젝트에서는 **Recall(재현율)을 우선** 평가 지표로 설정하고, 특히 각 결함 유형별 Recall을 개별적으로 분석하여 "어떤 결함이 가장 놓치기 쉬운지"를 파악한다.

### 8.3 오분류 패턴 분석

혼동행렬에서 높은 오분류율을 보이는 클래스 쌍을 식별하고, 해당 이미지를 시각적으로 비교하여 **"왜 혼동이 발생하는가"**에 대한 도메인 인사이트를 도출한다.

- 예상 혼동 쌍: Crazing ↔ Scratches (선형 패턴 유사성)
- 예상 혼동 쌍: Patches ↔ Rolled-in Scale (면적형 결함 유사성)

## 부록: 예상 Q&A

| 질문 | 답변 방향 |
|------|-----------|
| "왜 딥러닝이 아닌 전통 ML을 선택했는가?" | 본 프로젝트의 핵심은 OpenCV 전처리의 효과를 검증하는 것이며, 전통 ML에서의 전처리 효과가 명확히 드러남. 딥러닝은 향후 확장 과제로 계획 중 |
| "실제 제조 현장에서도 적용 가능한가?" | 본 파이프라인은 개념 검증(PoC) 단계이며, 실 적용 시 조명·카메라 캘리브레이션·실시간 처리 등 추가 엔지니어링이 필요함을 인지하고 있음 |
| "6클래스 중 가장 분류가 어려운 결함은?" | EDA 및 혼동행렬 분석 결과를 바탕으로 구체적 수치와 함께 답변 (예: Crazing과 Scratches의 혼동률) |
| "전처리 조합은 어떻게 선정했는가?" | 강의에서 학습한 기법을 체계적으로 조합하고, 결함 유형별 시각적 특성을 고려하여 실험 설계 |
| "모델 성능이 기대에 미치지 못하면?" | 성능 자체보다 "왜 그런 결과가 나왔는지" 분석하는 것이 더 중요하며, 분석 과정에서 인사이트를 도출하는 데 집중 |
