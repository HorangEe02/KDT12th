# Streamlit 2-모드 재구성 브레인스토밍

> **목표**: 기존 8탭 단일 구조를 **"부품 결함 자동 검수 시뮬레이터"**와 **"알고리즘 인사이트"** 두 모드로 분리하여, 사용 목적에 따라 최적화된 UI/UX를 제공한다.

---

## 1. 현재 구조 분석

### 기존 8탭 (단일 모드)

| # | 탭 이름 | 성격 | 주요 기능 |
|---|--------|------|----------|
| 1 | 결함 분석 | 혼합 | 전처리 시각화 + 특징 추출 + NB01~03 갤러리 |
| 2 | Stage1: 이진 분류 | 혼합 | 실시간 추론 + ML/DL 성능 비교표 + NB 갤러리 |
| 3 | Stage2: 결함 분류 | 혼합 | 실시간 추론 + ML/DL 비교 + NB 갤러리 |
| 4 | 이상 탐지 | 혼합 | AE/IF/OCSVM 추론 + 히트맵 + NB 갤러리 |
| 5 | 교차 도메인 검증 | 분석 | NEU→Severstal 전이 분석 (갤러리 위주) |
| 6 | 시스템 성능 | 분석 | 전처리 효과 지표 + 전체 NB 갤러리 (6카테고리) |
| 7 | 딥러닝 (NEU) | 혼합 | DL 추론 + Grad-CAM + NB 갤러리 |
| 8 | 통합 비교 | 분석 | 레이더 차트 + 파이프라인 도식 + KPI 종합 |

### 문제점
- **목적이 혼재**: "실제로 결함을 검사하고 싶은 사용자"와 "알고리즘을 이해하고 싶은 학습자"가 같은 화면을 봐야 함
- **정보 과부하**: 8탭 × 각 3~5 섹션 = 너무 많은 정보가 한 번에 노출
- **사용자 흐름 부재**: 실제 검수 시뮬레이션의 "이미지 투입 → 결과 확인"이라는 자연스러운 흐름이 없음

## 3. 모드 A: 부품 결함 자동 검수 시뮬레이터

### 컨셉
> **"공장 품질관리 담당자"**가 이미지를 투입하면, 2-Stage 파이프라인이 자동으로 결함 여부와 유형을 판정하는 **실용적 시뮬레이션 환경**.

### 사용자 페르소나
- 공장 QC 담당자, 품질관리 엔지니어
- "이 이미지가 정상인지 결함인지, 결함이면 어떤 유형인지 빠르게 알고 싶다"

### 탭 구성 (4탭)

#### 탭 A-1: 🔍 실시간 검수 (핵심 탭)

**목표**: 이미지 1장 투입 → 전체 2-Stage 파이프라인 자동 실행 → 결과 한눈에 확인

```
┌─────────────────────────────────────────────────────────────┐
│ [이미지 입력]              │ [검수 결과 대시보드]              │
│                            │                                  │
│  원본 이미지               │  ┌──────────────────────────┐   │
│  ┌──────────┐              │  │ 판정: ⚠️ 결함 감지        │   │
│  │          │              │  │ Stage1 (이진): 비정상 98% │   │
│  │  256×256 │              │  │ Stage2 (분류): LS 87%     │   │
│  │          │              │  │ 이상탐지: 이상 스코어 0.72│   │
│  └──────────┘              │  │ 총 추론시간: 42ms        │   │
│                            │  └──────────────────────────┘   │
│  전처리 후                 │                                  │
│  ┌──────────┐              │  [Stage2 확률 분포]              │
│  │  CLAHE   │              │  PS ████░░░░ 8%                 │
│  │ Applied  │              │  LS ████████████ 87%            │
│  └──────────┘              │  SS ██░░░░░░ 3%                 │
│                            │  RD █░░░░░░░ 2%                 │
├────────────────────────────┤                                  │
│ [이상탐지 히트맵]          │  [Grad-CAM 시각화]               │
│ 원본 → 히트맵 → 오버레이   │  AI가 어디를 보고 판단했는지      │
└─────────────────────────────────────────────────────────────┘
```

**핵심 기능**:
- **통합 추론**: 1장 입력 → Stage1(이진) + Stage2(분류) + 이상탐지 **동시 실행**
- **판정 카드**: 큰 글씨로 "✅ 정상" 또는 "⚠️ 결함 (유형: LS)" 표시
- **신뢰도 게이지**: 각 Stage별 신뢰도를 Progress Bar로 표시
- **이상탐지 히트맵**: 결함 위치를 빨간색 오버레이로 시각화
- **Grad-CAM**: DL 모델이 어디를 보고 판단했는지 설명 가능한 AI
- **추론 시간**: Stage1 + Stage2 합산 시간 (실시간 처리 가능 여부 판단용)

**기존 탭에서 가져오는 요소**:
- 탭2(Stage1 이진분류)의 실시간 추론 부분
- 탭3(Stage2 결함분류)의 실시간 추론 부분
- 탭4(이상탐지)의 히트맵 시각화 부분
- 탭7(딥러닝)의 Grad-CAM 시각화 부분

#### 탭 A-2: 📊 검수 이력 / 배치 분석

**목표**: 여러 이미지를 한 번에 분석하거나, 검수 결과를 누적하여 통계적으로 확인

```
┌─────────────────────────────────────────────────────────────┐
│ [배치 검수 모드]                                             │
│                                                              │
│ 📁 폴더 업로드 또는 다중 이미지 업로드                        │
│                                                              │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 총 검수: 50장 │ 정상: 38장 (76%) │ 결함: 12장 (24%)      │ │
│ │ PS: 3장 │ LS: 4장 │ SS: 3장 │ RD: 2장                   │ │
│ └──────────────────────────────────────────────────────────┘ │
│                                                              │
│ [결함 이미지 갤러리]          [통계 차트]                     │
│ ┌───┐ ┌───┐ ┌───┐          ┌──────────┐                    │
│ │LS │ │PS │ │SS │          │ 파이차트  │                    │
│ │87%│ │92%│ │71%│          │ 결함분포  │                    │
│ └───┘ └───┘ └───┘          └──────────┘                    │
└─────────────────────────────────────────────────────────────┘
```

**핵심 기능**:
- **다중 이미지 업로드**: st.file_uploader(accept_multiple_files=True)
- **배치 결과 요약**: 정상/결함 비율, 결함 유형별 분포
- **결함 이미지 갤러리**: 결함으로 판정된 이미지만 모아서 표시 (썸네일 + 판정결과)
- **검수 보고서 다운로드**: CSV/PDF 형태로 결과 내보내기 (선택적)

**신규 요소** (기존에 없던 기능):
- 배치 처리 로직
- 결과 누적/통계
- 보고서 생성

#### 탭 A-3: ⚙️ 파이프라인 설정

**목표**: 검수에 사용할 모델/전처리 조합을 선택하고 최적 설정을 구성

```
┌─────────────────────────────────────────────────────────────┐
│ [전처리 설정]                                                │
│ ☑ CLAHE (clip=2.0)  ☑ Bilateral (d=9)  ☑ Adaptive Sharpen  │
│                                                              │
│ [Stage1 모델 선택]                                           │
│ ○ ML: LightGBM (81.6%, 빠름)                                │
│ ● DL: ResNet-18 (93.3%, 정확)                                │
│                                                              │
│ [Stage2 모델 선택]                                           │
│ ○ ML: LightGBM (78.8%)                                      │
│ ● DL: ResNet-18 FE (88.6%)                                   │
│                                                              │
│ [이상탐지 활성화]                                             │
│ ☑ 활성화  모델: Autoencoder  임계값: 자동(Otsu)               │
│                                                              │
│ [현재 설정 요약]                                              │
│ 예상 추론시간: ~45ms/장  |  예상 정확도: Stage1 93.3%         │
└─────────────────────────────────────────────────────────────┘
```

**핵심 기능**:
- 전처리 ON/OFF + 파라미터 조정 (기존 사이드바에서 이동)
- Stage1/Stage2 모델 선택 (ML vs DL)
- 이상탐지 활성화/비활성화 + 임계값 조정
- 설정 조합별 예상 성능/속도 표시

**기존 탭에서 가져오는 요소**:
- 기존 사이드바의 전처리 설정 패널
- 탭2/3의 모델 선택 드롭다운

#### 탭 A-4: 📋 시스템 정보

**목표**: 현재 시스템의 데이터셋, 모델 파일 상태, 버전 정보 확인

**핵심 기능**:
- 데이터셋 통계 (75,408 패치, 클래스별 분포)
- 모델 파일 존재 여부 체크 (✅/❌ 표시)
- 시스템 환경 (Python, PyTorch, MPS/CUDA 상태)
- 버전 정보

## 4. 모드 B: 알고리즘 인사이트

### 컨셉
> **"K-Digital Training 수강생/발표 청중"**이 프로젝트의 알고리즘, 실험 과정, 성능 비교를 깊이 이해하기 위한 **교육·분석 환경**.

### 사용자 페르소나
- K-Digital Training 수강생, 강사, 발표 심사위원
- "이 프로젝트가 어떤 알고리즘을 썼고, 왜 이 선택이 최적인지 알고 싶다"

### 탭 구성 (5탭)

#### 탭 B-1: 🎨 전처리 분석

**목표**: 소주제 1~3의 전처리 파이프라인을 단계별로 시각화하고 효과를 정량적으로 확인

```
┌─────────────────────────────────────────────────────────────┐
│ [전처리 파이프라인 시각화]                                    │
│ 원본 → CLAHE → Bilateral → Adaptive Sharpen → Opening       │
│ ┌───┐  ┌───┐  ┌───┐  ┌───┐  ┌───┐                         │
│ │   │→ │   │→ │   │→ │   │→ │   │                         │
│ └───┘  └───┘  └───┘  └───┘  └───┘                         │
│ ED=0.107      ED=0.082      ED=0.029                        │
│                                                              │
│ [특징 추출 시각화]                                            │
│ HOG 히트맵 │ LBP 히스토그램 │ Canny 에지맵                   │
│                                                              │
│ [NB01~03 실험 결과 갤러리]                                   │
│ ▶ NB01: 정렬/ROI (7장) │ ▶ NB02: 필터링 (6장)              │
│ ▶ NB03: 에지/윤곽선 (7장)                                    │
└─────────────────────────────────────────────────────────────┘
```

**기존 탭에서 가져오는 요소**:
- 탭1(결함 분석)의 전처리 파이프라인 시각화
- 탭1(결함 분석)의 특징 추출 시각화 (HOG/LBP/Canny)
- 탭1(결함 분석)의 NB01~03 갤러리
- 탭6(시스템 성능)의 전처리 효과 지표 (ED/LV 전후 비교)
- 탭6(시스템 성능)의 NB01~03 갤러리

#### 탭 B-2: 🤖 ML vs DL 분류 비교

**목표**: 7가지 ML 모델과 2가지 DL 모델의 성능을 Stage1/Stage2 모두에서 비교 분석

```
┌─────────────────────────────────────────────────────────────┐
│ [Stage1: 이진 분류 — 정상 vs 비정상]                         │
│ ┌──────────────────┐  ┌──────────────────────────────────┐  │
```

**기존 탭에서 가져오는 요소**:

- 탭3(Stage2 결함분류)의 ML 성능 비교, DL KPI, ML vs DL 통합 차트, NB 갤러리
- 탭6(시스템 성능)의 NB04~05 갤러리

## 8. 핵심 신규 기능: 통합 추론 (A-1)

### 현재 vs 제안

| 현재 | 제안 (A-1) |
|------|-----------|
| Stage1 추론은 탭2에서 | **한 번에 전체 파이프라인 실행** |
| Stage2 추론은 탭3에서 | Stage1 → 결함 시 자동으로 Stage2 |
| 이상탐지는 탭4에서 | 이상탐지도 동시 실행 |
| Grad-CAM은 탭7에서 | DL 사용 시 Grad-CAM 자동 표시 |
| 결과를 각 탭에서 개별 확인 | **하나의 "검수 결과 카드"로 통합** |

### 통합 추론 함수 (신규)

```python
def run_full_inspection(image, config):
    """전체 2-Stage + 이상탐지 파이프라인 실행"""
    results = {}

    # 1. 전처리
    preprocessed = preprocess_pipeline(image, **config.preprocess)

    # 2. Stage 1: 이진 분류
    if config.stage1_model == 'DL':
        s1_result = dl_binary_predict(preprocessed)
    else:
        s1_result = ml_binary_predict(preprocessed)
    results['stage1'] = s1_result

    # 3. Stage 2: 결함이면 4종 분류
    if s1_result['prediction'] == 1:  # 결함
        if config.stage2_model == 'DL':
            s2_result = dl_defect4_predict(preprocessed)
        else:
            s2_result = ml_defect4_predict(preprocessed)
        results['stage2'] = s2_result

    # 4. 이상탐지 (병렬)
    if config.use_anomaly:
        ad_result = anomaly_detect(preprocessed)
        results['anomaly'] = ad_result

    # 5. Grad-CAM (DL 사용 시)
    if config.stage1_model == 'DL' or config.stage2_model == 'DL':
        results['gradcam'] = generate_gradcam(preprocessed)

    return results
```

### 최소 구현 범위 (MVP)

1. **모드 전환** (st.radio)
2. **모드 A**: A-1(통합 추론) + A-3(설정, 기존 사이드바 이동)
3. **모드 B**: 기존 탭1~8을 5탭으로 재배치
