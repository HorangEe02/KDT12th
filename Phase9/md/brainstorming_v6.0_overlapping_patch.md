## 1. 변경 배경 및 동기

### 1.1 경계 결함 누락 문제

현재 v5.1에서는 256 x 1,600 원본 이미지를 **Stride=256**(비겹침)으로 분할하여 약 6개의 256 x 256 패치를 생성한다. 이 방식에서 패치 경계(x=256, 512, 768, 1024, 1280)에 걸쳐 있는 결함은 다음과 같은 문제를 발생시킨다:

```
[원본 이미지 256 x 1,600]
├── 패치 1 (x: 0~255)
├── 패치 2 (x: 256~511)    ← 경계: x=256
├── 패치 3 (x: 512~767)    ← 경계: x=512
├── 패치 4 (x: 768~1023)   ← 경계: x=768
├── 패치 5 (x: 1024~1279)  ← 경계: x=1024
└── 패치 6 (x: 1280~1535)  ← 경계: x=1280
    ※ 마지막 64px (x: 1536~1599) 미포함
```

- **문제 1**: 경계에 걸친 결함이 두 패치로 분리 → 양쪽 모두 결함 비율이 `MIN_DEFECT_RATIO(0.01)` 미만이 되어 **정상으로 오분류** 가능
- **문제 2**: 결함의 형태학적 특성(연속성, 크기)이 패치 분할로 왜곡
- **문제 3**: 마지막 64px 영역(x=1536~1599)이 완전히 누락

### 1.2 해결 전략: 50% 오버랩 패치

Stride를 128로 변경하면 인접 패치 간 50% 영역이 겹치게 되어, 기존 경계 위치의 결함이 **인접 패치의 중앙부에 완전히 포함**된다.

```
[v6.0 오버랩 패치 분할]
패치 1:  x=0────────x=255
패치 2:     x=128────────x=383      ← 패치 1-2 겹침: x=128~255
패치 3:        x=256────────x=511   ← 기존 경계(x=256)가 중앙부에 포함
패치 4:           x=384────────x=639
...
패치 11:                        x=1280────────x=1535
패치 12:                           x=1344────────x=1599  ← 끝단 정렬 패치
```

## 3. 변경 목표 (v6.0)

### 3.1 패치 분할 변경

| 항목                     | v5.1 (현재)    | v6.0 (목표)                    |
| ------------------------ | -------------- | ------------------------------ |
| **Stride**         | 256 (비겹침)   | **128 (50% 오버랩)**     |
| **패치 수/이미지** | ~6장           | **~11장** (끝단 포함 12) |
| **총 패치 수**     | ~75,408장      | **~137,000장** (1.83배)  |
| **경계 결함 포착** | 불가           | **가능**                 |
| **끝단 64px**      | 누락           | **포함** (끝단 정렬)     |

### 3.2 수치 계산

```
원본 이미지 너비: 1,600px
패치 크기: 256px
Stride: 128px

정규 패치 시작점: range(0, 1600-256+1, 128)
 = range(0, 1345, 128)
 = [0, 128, 256, 384, 512, 640, 768, 896, 1024, 1152, 1280]
 = 11개 패치

마지막 유효 시작점: 1280 → 끝점 1280+256 = 1536
미포함 영역: x=1536~1599 (64px)

끝단 정렬 패치 추가: x=1344 → 끝점 1344+256 = 1600
총 패치 수: 11 + 1 = 12개/이미지

총 예상 패치 수: 12,568장 x 12패치 = ~150,816장
 (정규 11패치 기준: 12,568 x 11 = ~138,248장)
```

### 3.3 데이터 분포 예상 변화

```
v5.1 (Stride=256):
├── Normal:  60,322장 (79.9%)
└── Defect:  15,086장 (20.1%)

v6.0 (Stride=128) 예상:
├── Normal:  ~110,000장 (추정, 비율 유사)
└── Defect:  ~27,000~40,000장 (추정, 경계 결함 추가 포착으로 증가 가능)
    ※ 오버랩으로 인해 결함 패치 비율이 소폭 상승할 가능성
    ※ 정확한 수치는 패치 재생성 후 확정
```

## 4. 기술적 분석

### 4.1 경계 결함 포착 메커니즘

```
[v5.1] 경계에 걸친 결함 → 누락
─────────────┬───────────────
  패치 A     │     패치 B
  결함 10%   │    결함 8%
  → 정상?    │   → 정상?       ← MIN_DEFECT_RATIO(1%) 초과하지만
                                  결함이 분리되어 형태 왜곡

[v6.0] 오버랩으로 결함 완전 포함
─────────────┬───────────────
  패치 A     │     패치 B
        ┌────┴────┐
        │ 패치 A' │              ← 오버랩 패치가 결함을 중앙에 완전 포함
        │ 결함18% │
        └─────────┘
```

### 4.2 데이터 중복 영향 분석

| 영향 항목                 | 설명                                                     | 대응 전략                              |
| ------------------------- | -------------------------------------------------------- | -------------------------------------- |
| **학습 데이터 상관** | 동일 영역 최대 2개 패치에 포함 → 과적합 위험              | 이미지 단위 Train/Val/Test 분할 필수   |
| **학습 시간 증가**   | 패치 수 1.83배 → 에폭당 학습 시간 비례 증가              | 배치 크기 조정 또는 에폭 수 감소 검토  |
| **메모리 사용량**    | 패치 수 증가 → 메모리 부담 증가                          | max_per_class 파라미터로 샘플링 제어   |
| **앙상블 효과**      | 추론 시 동일 영역 복수 예측 → 소프트 보팅 가능           | 오버랩 영역 확률 평균/투표 병합 로직   |
| **데이터 누수**      | 동일 이미지 패치가 Train/Test에 분산 → 성능 과대 추정    | **이미지 ID 기반 분할 철저 적용** |

### 4.3 마지막 패치 처리 전략 비교

| 전략                       | 패치 수 | 장점                  | 단점                          |
| -------------------------- | ------- | --------------------- | ----------------------------- |
| **A. 무시**          | 11장    | 구현 단순             | 마지막 64px 누락              |
| **B. 끝단 정렬 추가** | 12장    | 끝단 결함 포착 가능   | stride 불일치 (128→64)       |
| **C. 패딩 후 분할**   | 12장    | stride 균일           | 패딩 영역 노이즈 유입 가능    |

> **권장: 전략 B (끝단 정렬 추가)** — x=1344에서 시작하는 마지막 패치를 추가하여 끝단 결함도 포착. stride 불일치는 추론 시 병합 가중치로 보정 가능.

### 4.4 MIN_DEFECT_RATIO 임계값 재검토

오버랩 패치에서는 결함이 패치 중앙에 더 완전하게 포함되므로, 결함 비율이 더 높은 패치가 생성될 가능성이 있다.

| 항목                          | v5.1          | v6.0 검토                      |
| ----------------------------- | ------------- | ------------------------------ |
| `MIN_DEFECT_RATIO`          | 0.01 (1%)     | 유지 또는 소폭 상향 (0.02~0.05) |
| **근거**                | 최소 결함 존재 | 오버랩으로 부분 결함 패치 증가, 노이즈 수준 결함 필터링 필요 여부 확인 |

## 9. 추론 파이프라인 변경

### 9.1 기존 추론 흐름 (v5.1)

```
입력 이미지 (256 x 1,600)
    │
    ├── 패치 1~6 (stride=256, 비겹침)
    │
    ├── 각 패치 → 개별 예측 (정상/결함)
    │
    └── 이미지 레벨 판정: 패치 중 하나라도 defect → defect
```

### 9.2 변경 추론 흐름 (v6.0)

```
입력 이미지 (256 x 1,600)
    │
    ├── 패치 1~12 (stride=128, 50% 오버랩)
    │
    ├── 각 패치 → 개별 예측 (정상/결함 + 확률)
    │
    ├── 오버랩 영역 병합:
    │   ├── 방법 A: 확률 평균 (Soft Voting)
    │   ├── 방법 B: 최대 확률 (Max Pooling)
    │   └── 방법 C: 다수결 투표 (Majority Voting)
    │
    └── 이미지 레벨 판정: 병합된 결과 기반 최종 판정
```

### 9.3 오버랩 병합 전략 비교

| 전략                        | 장점                  | 단점                      | 권장 용도     |
| --------------------------- | --------------------- | ------------------------- | ------------- |
| **확률 평균 (Soft)**  | 부드러운 예측, 노이즈 감소 | 약한 결함 신호 희석 가능  | DL 모델 추론  |
| **최대 확률 (Max)**   | 결함 민감도 최대화    | False Positive 증가 가능  | Recall 우선   |
| **다수결 (Majority)** | 안정적, 노이즈 강건   | 미세 결함 놓칠 가능       | ML 모델 추론  |

| **추론 앙상블 효과**      | 없음           | 오버랩 소프트 보팅 도입        |

### 12.2 정성적 기대 효과

1. **경계 결함 완전 포착**: 패치 경계에 걸친 결함을 100% 검출 가능
2. **추론 신뢰도 향상**: 오버랩 영역의 복수 예측으로 앙상블 효과
3. **데이터 다양성 증가**: 같은 결함을 다른 위치에서 관찰 → 모델 일반화 향상
4. **끝단 영역 보완**: 마지막 64px 영역까지 검사 가능
5. **산업 적용 현실성**: 실제 제조 라인에서도 오버랩 스캔이 표준 관행

### 12.3 Trade-off 분석

| 비용                      | 이득                            |
| ------------------------- | ------------------------------- |
| 학습 데이터 1.83배 증가   | 경계 결함 100% 포착             |
| 학습 시간 ~1.8배 증가     | 추론 시 앙상블 효과             |
| 저장 공간 ~1.8배 증가     | 모델 일반화 성능 향상 기대      |
| 추론 시간 ~2배 증가       | 추론 신뢰도 향상                |

> **결론**: 학습/추론 비용 증가는 선형적이지만, 경계 결함 포착과 앙상블 효과로 인한 품질 향상은 **제조업 실무에서 불량 유출 방지**라는 핵심 목표에 직접 기여하므로 **비용 대비 효과가 충분**하다.
