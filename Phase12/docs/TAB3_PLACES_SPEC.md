# 🍽️ Tab 3. 주변 플레이스 — 기능 설명서

> **"경기 전에 뭐 먹고, 경기 후엔 어디서 자고, 다음날 뭐 보지?"**
> 원정 응원은 경기 관람이 끝이 아닙니다. 그 주변 반나절·하룻밤의 동선까지가 **진짜 원정**입니다. 이 탭은 그 "주변"을 한 번에 정리해 줍니다.

**라우트**: `/places` · **배포 URL**: [my-web-app--mini12-310f5.asia-east1.hosted.app/places](https://my-web-app--mini12-310f5.asia-east1.hosted.app/places)

---

## 📖 起 (기) — 왜 필요한가? 문제 제기

### 원정 응원, 경기 주변이 진짜 숙제

팬이 원정 전에 준비하는 일은 경기 티켓이 전부가 아닙니다:

> **고민 1 — "경기장 근처 맛있는 거 뭐 있지?"**
> 네이버 블로그 "사직야구장 맛집 BEST 10" 포스트 5~6개를 돌려본 뒤, 또 인스타 해시태그로 실물 사진 확인… 이 과정을 반복합니다.
>
> **고민 2 — "야구 끝나면 늦는데, 어디서 자지?"**
> 호텔·모텔 예약 앱을 따로 열고, 또 경기장과의 거리를 카카오맵으로 다시 잰 뒤 비교.
>
> **고민 3 — "멀리 왔는데 한 곳만 들러도 아깝잖아."**
> 경기 외 **관광지**까지 챙기려면 여행 앱을 또 따로 열어야 합니다.

맛집·숙소·관광지는 결국 **"경기장 주변 반경 2km 안"** 에 대부분 분포하는데도, 각각 다른 앱에 흩어져 있어 매번 같은 검색을 반복하는 상황.

### 이 탭의 약속

**"한 구장을 선택하면 · 주변 음식점·숙박·관광지 100여 곳을 · 거리순으로 정리해 · 카드와 지도로 한 번에."** 데이터 출처는 **정부 공식 관광 DB (TourAPI)** 입니다.

## 🚀 承 (승) — 무엇을 하는가? 기능 소개

### 기능 6가지

#### 1. 구장 선택 (10개 구장 원터치)
- 상단의 **10 칩 버튼** 으로 어느 구장이든 즉시 전환
- 잠실 · 고척 · 수원 · 인천 · 광주 · 대전 · 창원 · 사직 · 대구 · 한화
- URL에도 반영되어 친구에게 "이 구장 주변" 을 링크로 공유 가능

#### 2. 카테고리 필터 (3탭)
- **🍽 음식점** · **🏨 숙박** · **🎡 관광지** 를 탭으로 전환
- 각 탭 옆에 개수 표시 (예: "음식점 27 · 숙박 25 · 관광지 25")

#### 3. 거리순 자동 정렬
- 경기장에서 **가까운 순서대로** 자동 정렬
- 500m 이내 장소에는 **"추천"** 배지 표시
- "걸어갈 수 있는 거리" 가 한눈에 보임

#### 4. 검색 (모바일 특화)
- 제목에 특정 단어 포함한 장소만 필터링
- 예: "호텔" 검색 → 숙박 카테고리에서 호텔만 남김

#### 5. 더 보기 버튼 (페이지네이션)
- 처음엔 **12개만** 보여주고, "더 보기" 탭하면 12개씩 추가
- 예: `12 / 87` → `24 / 87` → `36 / 87` ... 전체 도달 시 버튼 자동 숨김
- 한 번에 다 보여주면 느려지기 때문에 **점진적 로딩**

#### 6. TOP 10 위치 지도 + 거리×평점 산점도 (데스크톱)
- **TOP 10 위치 지도**: 경기장 반경 500m 점선 원 + 상위 10곳 마커
- 마커 클릭 ↔ 아래 카드 자동 스크롤 (양방향 연동)
- **거리×평점 산점도**: 가로축=거리, 세로축=평점 → **"가깝고 평점 높은" 최적 지점** 한눈에 발견

### 화면 예시

**💻 데스크톱**
```
┌─ 🍽 경기장 주변 맛집 · 숙소 · 관광지 ─────────────┐
│ 잠실야구장 · 서울                                   │
├─ [잠실] [고척] [수원] [인천] ... [대구]             │
├─ 🍽 음식점 27 · 🏨 숙박 25 · 🎡 관광지 25           │
├─ [음식점] [숙박] [관광지]                            │
├─ 📍 TOP 10 위치 지도 (500m 점선 원 + 마커) ────────┤
├─ 🧾 TOP 10 카드 그리드 (3열) ──────────────────────┤
│ [카드] [카드] [카드]                                 │
│ [카드] [카드] [카드] ...                             │
├─ 📊 거리 × 평점 산점도 ──────────────────────────┤
└────────────────────────────────────────────────────┘
```

**📱 모바일**
- 상단 **가로 스크롤 구장 칩**
- 아래 **검색바** + **카테고리 칩** + **세로 카드 리스트**
- 우하단 **🗺 플로팅 버튼** (FAB) → 지도 탭으로 연결
- 리스트 맨 아래 **"12개 더 보기 (12/87)"** 버튼

## ⚙️ 轉 (전) — 어떻게 만들었는가? 기술과 원리

> 이 탭의 핵심 기술을 **비유와 예시**로 풀어씁니다.

### 🏛️ TourAPI — "정부 공식 관광 DB"

**쉽게 말하면**:
> "한국관광공사(KTO)가 전국의 음식점·숙박·관광지 정보를 모아 **누구나 사용할 수 있도록 열어놓은 공공 데이터 창구**입니다."

- 운영 주체: 한국관광공사 (공공기관)
- 비용: 무료 (일 호출 제한 있음)
- 장점: **공식 출처** 이므로 블로그·인스타와 달리 정보가 상대적으로 정확
- 단점: 최신 팝업 매장·트렌드 맛집은 반영이 느릴 수 있음

**수집 방식**:
```
🏛 TourAPI
   │ "경기장 좌표 중심 2km 반경, 카테고리별 최대 100건"
   ▼
📂 구장별로 미리 캐시 (빌드 타임)
   · 잠실_food.json · 잠실_stay.json · 잠실_tour.json
   · ... (10 구장 × 3 카테고리 = 30개 파일, 총 600KB)
   ▼
웹 페이지 진입 시 해당 구장의 3개 파일만 읽음
```

**왜 미리 캐시?**: 사용자가 접속할 때마다 TourAPI를 부르면 느리고, API 호출 제한에 걸립니다. 그래서 **빌드 타임에 한 번만 수집** 해서 파일로 저장한 뒤, 사용자에게는 파일을 바로 돌려줍니다.

### 📏 거리순 정렬 — "경기장에서 가까운 순서대로"

TourAPI가 각 POI(Point of Interest, 장소)에 이미 **경기장까지의 거리 (m 단위)** 를 포함해 줍니다. 우리는 그 숫자를 기준으로 오름차순 정렬.

```ts
// 거리가 가까운 순서대로
active.sort((a, b) => a.dist_m - b.dist_m)
```

500m 이내 장소에는 자동으로 **"추천" 배지**를 붙입니다. 비유: "마트에서 '5분 거리' 라벨 붙은 상품" 같은 시각 힌트.

### 📄 URL 페이지네이션 — "12개씩 끊어서 점진적으로"

**쉽게 말하면**:
> "인스타그램 피드처럼 스크롤 내릴 때마다 더 불러오는 방식인데, **URL에 현재 '몇 개까지 봤는지' 를 저장**합니다."

```
처음 접속: /places?s=잠실
   → 12개 표시 + "12개 더 보기" 버튼

"더 보기" 탭
   → URL 갱신: /places?s=잠실?limit=24
   → 24개 표시 + "12개 더 보기" 버튼

...

87개 도달
   → 버튼 자동 제거
```

**왜 URL에?**:
- 사용자가 "36개 본 상태"를 친구에게 그대로 공유 가능
- 브라우저 뒤로가기로 이전 상태 복원 가능
- 새로고침해도 스크롤 위치 유지

### 📊 Plotly 거리×평점 산점도 — "두 축에 점 찍어 최적 지점 찾기"

**쉽게 말하면**:
> "x축에 거리(m), y축에 평점을 놓고 모든 음식점을 점으로 찍습니다. **왼쪽 위** 에 몰린 점들이 '가깝고 평점 높은 곳'."

- 마커 크기: 가까울수록 큼 (= 방문 추천도)
- 색상: 카테고리별 구분
- 상호작용: 점 클릭 시 이름·주소 툴팁

**왜 산점도?**: 표·카드는 "이 중에 뭐가 최적이야?" 질문에 답하기 어렵습니다. 산점도 한 장이면 **눈으로 즉시** 답을 찾을 수 있습니다.

### 🔗 마커 ↔ 카드 양방향 연동 — "지도와 리스트가 서로 말을 걸다"

- 지도 마커 클릭 → URL `?p={장소ID}` 갱신 → 해당 카드로 자동 스크롤 + 하이라이트
- 카드 클릭 → 지도 마커 popup 자동 오픈

비유: **"지도에서 '이거 뭐야?' 찍으면, 리스트에서 '이거야!' 답해주는 대화형 UI"**

### 📱 Floating Action Button (FAB) — "우하단에 떠 있는 동그란 버튼"

iOS/Material Design의 대표 UI 패턴. 모바일에서 우하단에 고정된 원형 버튼을 눌러 Tab 2 (지도) 로 즉시 이동합니다. Gmail·지도 앱의 "+" 버튼과 동일한 개념.

### 🔗 데이터 흐름 한눈에 보기

```
🏛 TourAPI
   │ 빌드 타임 수집
   ▼
📂 public/data/poi/{구장}_{카테고리}.json
   │
   │ 사용자 진입
   ▼
 ┌────────────────────────────────────┐
 │ 선택 구장의 food · stay · tour 로드 │
 │ 거리순 정렬 · limit 범위 자르기     │
 └────────────────────────────────────┘
   │
   ├─ 데스크톱 → 지도 + 카드 + 산점도
   └─ 모바일 → 카드 + "더 보기" 버튼 + FAB
```

## 🎯 結 (결) — 어떤 가치를 만들었는가? 결과와 의미

### 숫자로 본 성과

| 지표 | 결과 |
|---|---|
| 데이터 규모 | 10 구장 × 3 카테고리 = **30개 JSON 파일** · 총 ~600KB |
| 첫 진입 로딩 | **12개 카드 약 1초** (FCP 기준) |
| "더 보기" 동작 | 12 → 24 → 36 → ... 연속 확장 **PASS** |
| 모바일 자동 테스트 | iPhone SE · 14 Pro · iPad **전 환경 통과** |
| 라이브 주소 | [배포 완료 ✅](https://my-web-app--mini12-310f5.asia-east1.hosted.app/places) |

### 사용자에게 남기는 것

**"경기장 주변 100여 곳을 · 한 번의 클릭으로 · 공공 데이터 기반으로 · 거리순 정리."**

- 블로그 서핑·인스타 해시태그 순회 **없이** 핵심 정보 즉시 확보
- 500m 이내 "추천" 배지로 **도보 범위** 빠르게 선별
- 산점도로 **"가깝고 평점 높은"** 한 점을 눈으로 찾아냄
- Tab 2 (지도) 로 원터치 이동 가능

### 기술적 의의

- **공공데이터 + 정적 생성**: TourAPI를 빌드 타임에 미리 수집 → 런타임 API 호출 0건, 안정성·속도 극대화
- **URL 기반 페이지네이션**: 북마크 · 공유 · 뒤로가기가 자연스럽게 동작. SEO에도 유리
- **마커 ↔ 카드 양방향 UX**: 지도와 리스트를 단순 병치하지 않고 **대화형으로 연결**
- **모바일 카드 + 플로팅 FAB**: 원터치로 "주변 정보 → 경로 생성" 흐름 완결

## 🔍 부록 — 개발자용 상세 정보

아래는 코드를 다루는 개발자를 위한 참조입니다. 일반 독자는 건너뛰어도 좋습니다.

### A. POI 데이터 스키마

```ts
interface POI {
  content_id: string;        // TourAPI 고유 ID
  title: string;             // POI 이름
  addr?: string;             // 주소
  tel?: string;              // 전화번호
  lat: number;               // 위도
  lng: number;               // 경도
  dist_m?: number;           // 경기장에서의 거리 (m)
  first_image?: string;      // 대표 이미지 URL (옵션)
  category: "food" | "stay" | "tour";
}
```

### B. 쿼리 파라미터

| Param | 기본값 | 설명 |
|---|---|---|
| `s` | `stadiums[0].short_name` | 구장 약칭 |
| `cat` | `"food"` | 카테고리 (food/stay/tour) |
| `p` | 없음 | 선택된 POI content_id |
| `q` | 없음 | 검색어 (모바일) |
| `limit` | `12` (max 500) | 모바일 카드 개수 |
