## 📖 起 (기) — 왜 필요한가? 문제 제기

### 야구팬의 3가지 불편

원정 응원을 계획하는 팬은 매번 이런 질문과 마주칩니다:

> **질문 1 — "다음 원정 경기가 언제지?"**
> KBO 공식 앱과 구단 앱을 번갈아 열어야 하고, 원정과 홈 경기가 섞여 있어 원정만 골라내기 번거롭습니다.
>
> **질문 2 — "우리 팀이 거기 가면 잘해?"**
> 구장별 원정 승률은 팀 공식 채널에서도 잘 정리되어 있지 않습니다.
>
> **질문 3 — "이번 경기는 이길 것 같아?"**
> 승부를 점치는 "감"은 있지만, 데이터 기반의 합리적 근거는 찾기 어렵습니다.

### 이 탭의 약속

**"경기 일정 · 팀별 원정 성적 · AI 승률 예측"** 을 한 페이지에서 제공합니다. 사용자는 응원팀을 고르기만 하면, 나머지는 시스템이 자동으로 정리해 줍니다.

## 🚀 承 (승) — 무엇을 하는가? 기능 소개

### 기능 4가지

#### 1. 원정 경기 일정 자동 필터
- 응원팀 선택 → 해당 팀이 **원정으로 나가는 경기만** 자동 추출
- 기간 슬라이더(예: 4월~5월)로 원하는 구간만 좁혀보기 가능
- 경기 날짜 · 요일 · 상대팀 · 구장 · 중계 채널까지 한 줄 요약

#### 2. 승률 예측 게이지
- 선택한 경기에 대해 **"이길 확률 %"** 를 동그란 게이지로 시각화
- 예: `LG vs KT → 98.5%` (높을수록 응원팀 유리)
- 아래에서 설명할 **AI 모델**이 뒤에서 돌아갑니다

#### 3. 최근 3년 팀별 원정 승률 랭킹
- 10개 구단을 가로 막대로 비교
- 자신이 응원하는 팀은 팀 컬러로 강조
- "우리 팀은 원정 가면 잘하나?" 한눈에 판단

#### 4. 경기 상세 메타
- 경기를 클릭하면 → 선발투수, 중계 채널, 경기 상태 표시
- URL에도 선택 정보가 반영돼 친구에게 공유 가능

```
├─ [총경기] [시즌승률] [팀평균] ─────────────────────┤

```

- 다음 원정 경기 **대형 카드** (상대 로고·시간·구장·승률)
- 이후 6경기는 **세로 카드 그리드**로 스크롤 탐색

## ⚙️ 轉 (전) — 어떻게 만들었는가? 기술과 원리

> 여기부터는 비전공자도 이해할 수 있도록 **비유와 예시**로 설명합니다.

### 🧠 AI 승률 예측 모델 — "과거 데이터로 미래 확률 계산하는 수학"

**쉽게 말하면**:
> "KIA가 지난 3년간 원정 가서 60% 승률이었고, 한화가 홈에서 45% 승률이었다면, 오늘 한화 원정 가는 KIA는 **몇 %로 이길까?**"

**로지스틱 회귀 (Logistic Regression)** 라는 통계 모델이 이 계산을 담당합니다. 이름은 어려워 보이지만 원리는:

1. **과거 경기 데이터를 준다** → 수천 경기의 결과(승/패)
2. **5가지 힌트를 입력한다**
   - 우리 팀 원정 승률
   - 상대 팀 홈 승률
   - 우리 팀 순위
   - 상대 팀 순위
   - 두 팀 순위 차
3. **AI가 패턴을 학습한다** → "순위 차가 크고 원정 승률이 높으면 이길 확률이 올라간다" 같은 규칙 자동 발견
4. **새 경기를 예측한다** → 위 5가지 힌트만 주면 0~100% 확률 출력

**사용한 도구**: Python의 `scikit-learn` (머신러닝 분야 표준 라이브러리) 로 모델을 훈련 → TypeScript로 수식을 직접 옮겨 심음. 그 결과 **Python 원본과 TypeScript 버전의 예측값이 100% 일치**함을 확인했습니다 (4개 샘플 경기 대조).

### 📊 시각화 — Plotly.js

승률 게이지와 막대그래프는 **Plotly.js** 로 그렸습니다.
- 비유: 엑셀 차트를 더 예쁘고 인터랙티브하게 만들 수 있는 도구
- 장점: 사용자가 마우스 올리면 툴팁 표시, 막대 클릭 시 반응 등 상호작용 가능

### ⚡ Next.js 16 — "서버에서 미리 페이지 조립"

**쉽게 말하면**:
> 인스타그램처럼 사용자가 접속할 때 빈 화면이 뜨고 로딩돌아가는 방식이 아니라, **서버에서 완성된 페이지를 만들어서 보내주는 방식**입니다.

**장점**:
- 첫 화면이 빠르게 뜸 (**< 1초** 목표)
- 검색엔진(구글)이 페이지 내용을 잘 읽을 수 있음 (SEO 유리)
- 스마트폰·노트북 어디서 봐도 똑같이 보임

### 🛡️ Zod — "요청 검사하는 문지기"

API (서버와 데이터 주고받는 창구) 에는 악의적이거나 잘못된 요청이 들어올 수 있습니다. Zod는 각 요청을 **미리 정한 규칙**과 대조해서 걸러냅니다.

예: "LG vs XYZ" 같은 존재하지 않는 팀이 들어오면 즉시 400 에러로 차단.

## 🔍 부록 — 개발자용 상세 정보

아래는 코드를 직접 다루는 개발자를 위한 참조입니다. 일반 독자는 건너뛰어도 좋습니다.

### A. 승률 예측 모델 입출력

| 입력 피처 | 설명 |
|---|---|
| `team_away_win_rate` | 응원팀 최근 3년 원정 승률 |
| `opp_home_win_rate` | 상대팀 최근 3년 홈 승률 |
| `team_rank` · `opp_rank` | 각 팀 최근 시즌 순위 |
| `rank_diff` | `team_rank - opp_rank` |

- 파이프라인: `StandardScaler` + `LogisticRegression` (sklearn)
- 타깃: `team.win_rate > opp.win_rate` (균형 50/50)
- Fallback: 팀 스탯 없을 때 `prob = 0.45`

### B. API 명세

- `GET /api/predict?team=LG&opponent=KT`
- `POST /api/predict` body: `{ team, opponent }` (Zod 검증)
- 응답: `{ team, opponent, prob, source: "logreg" | "fallback" }`

### C. 쿼리 파라미터

| Param | 기본값 | 설명 |
|---|---|---|
| `team` | profile.favoriteTeam 우선 · `resolveTeam()` 가 결정 | 응원팀 |
| `start` · `end` | 시즌 개막 ~ 종료 | 기간 필터 |
| `game` | 없음 | 선택 경기 ID |
