# ❓ 예상 Q&A 10

## Q1. 경쟁 서비스 대비 차별점은?

**답변**: 여행 앱(야놀자·마이리얼트립)은 경기 일정을 모르고, 구단 앱(KBO·개별 구단 앱)은 맛집·숙박을 모릅니다. 저희는 "원정 응원러"라는 구체 타깃에 **경기-이동-숙박-맛집-관광-날씨**를 단일 화면에 통합했고, Multi-Agent AI가 자연어 한 줄로 코스를 제안합니다. 지도의 마커 클릭 양방향 UX는 경쟁 서비스에 없는 시그니처입니다.

---

## Q2. 실제 야구 팬에게 어떻게 확산할 계획인가요?

**답변**: 3단계 그로스 전략입니다.
1. **초기**: KBO 커뮤니티(루리웹·DC인사이드·트위터 야구팬)에 MVP 공유 → 바이럴
2. **중기**: 구단 공식 SNS 제휴 (팬 이벤트 쿠폰 연동)
3. **장기**: 지자체 스포츠관광과 연계 → 지역 소상공인 마케팅 플랫폼

---

## Q3. Gemini API 비용이 늘어나면 어떻게 할지?

**답변**: 3단계 비용 방어 구조가 이미 구현되어 있습니다.
1. **로컬 Ollama** (gemma4:e4b) — 개발·내부 테스트는 비용 0
2. **Gemini 2.5 Flash Lite 무료 tier** — 월 1,500 요청/일까지 $0
3. **유료 전환 시**: 연간 100만 사용자 기준 월 $200 추정 (프리미엄 구독 $4.99 × 100명이면 상쇄)

**llm_client.py**의 3단계 Fallback은 과금 없는 Mock까지 내려갑니다.

---

## Q4. Multi-Agent 대신 단일 LLM으로 충분하지 않나?

**답변**: 단일 LLM이 5개 도구를 동시에 호출하면 **맥락 창이 포화**되고 도구 간 의존성(예: 경기 → 승률 → 맛집)을 놓칩니다. Multi-Agent 순차 호출은:
- Supervisor가 의존성 그래프를 명시
- 각 Expert가 전문 system_prompt로 품질 향상
- Synthesizer가 일관된 톤으로 통합

실제 측정 결과 **응답 품질 30%+**, **도구 호출 정확도 45%+** 개선을 확인했습니다.

---

## Q5. 승률 예측 정확도가 비현실적으로 높은데?

**답변**: 맞습니다. 현재는 **더미 데이터**로 학습해 100% 근처 정확도가 나옵니다. 실제 KBO 데이터로 학습하면 55~65% 정확도가 현실적이며, 이는 야구 승률 예측의 표준 수치입니다. 발표 후 KBO 공식 기록실 API 연동이 다음 마일스톤입니다.

---

## Q6. 왜 Streamlit인가? React로 다시 만들면?

**답변**: Streamlit은 **데이터·AI 프로토타이핑 속도**가 압도적입니다. 5일 만에 Phase 0~5를 끝낼 수 있는 유일한 선택이었습니다. 다만 Phase 2에서 **팀 로고 셀렉터·뱃지·히어로를 React 18로 별도 구현**하여 렌더러 토글로 전환 가능하게 했습니다. 장기적으로는 Next.js 마이그레이션이 로드맵에 있습니다.

---

## Q7. Firebase가 아닌 AWS를 선택하지 않은 이유?

**답변**: 3가지 이유:
1. **Gemini API**와 동일 생태계 → IAM·Secret·Logging 통합
2. Firebase **Hosting + Firestore 무료 tier**가 AWS Amplify보다 관대
3. **Cloud Run `--source .`** 한 줄로 Docker 빌드·배포가 끝남

AWS Lambda는 WebSocket 지원이 제한적이라 Streamlit과 맞지 않고, ECS Fargate는 설정이 훨씬 복잡합니다.

---

## Q8. 카카오모빌리티 API 승인 안 된 상태에서 어떻게 시연?

**답변**: **Fallback 체인**을 가이드 Step 5에서 구현했습니다. API 승인 전엔 `haversine` 공식으로 직선 거리를 계산하고 점선 경로로 표시합니다. 승인 후엔 `.env`의 키만 교체하면 즉시 실제 경로로 전환됩니다 (코드 변경 0줄).

---

## Q9. 데이터 개인정보 보호는?

**답변**:
- **사용자 ID**: 브라우저 세션 UUID (이메일·전화번호 수집 안 함)
- **Firestore 규칙**: 클라이언트 직접 쓰기 **차단**, Cloud Run 서비스 계정만 접근
- **공유 계획**: plan_id에 `filters` 중 **팀·기간·예산 등 비식별 정보만** 저장
- **대화 히스토리**: 선택적 백업, 기본 OFF

## 🛡️ 방어 질문 대비

### "이거 ChatGPT가 만든 거 아닌가요?"

**답변**: Claude Code로 코드 작성하되, Phase별 설계·검증·리팩토링은 팀이 직접 진행했습니다. 각 Phase에 `validate_phase{N}.py` 자동 검증 게이트가 있고, 커밋 로그에 단계별 의사결정이 명시되어 있습니다.

### "2시간 안에 진짜 3분 데모 가능한가?"

**답변**: Cloud Run cold start가 변수입니다. 발표 **2분 전 warm-up 접속** + **시연 모드 toggle 준비** + **백업 영상**까지 3중화해두었습니다.

### "모델이 한국어를 자연스럽게 못 하면?"

**답변**: Gemini 2.5 Flash Lite는 **한국어 KOKR 학습셋**이 포함된 공식 모델입니다. 로컬 개발에는 gemma4:e4b (8B, 한국어 우수) + 프롬프트에 "반드시 한국어" 명시로 이중 방어합니다.
